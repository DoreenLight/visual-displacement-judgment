# 坐标系与外参

> D435i 的深度坐标系、IMU 坐标系、外参关系是踩坑高发区。这页汇总所有约定。

## 1. 深度坐标系约定

D435i 使用与 librealsense SDK 一致的坐标系：

```
        +Z（向右） ← 不用看了，正面朝你
         ↑
         |  
         |  
         |  
         ●─────→ +X（向右）
        /
       /
      ↓ +Y（向下）
```

**实际约定**（[librealsense Projection-in-RealSense-SDK-2.0](https://github.com/realsenseai/librealsense/wiki/Projection-in-RealSense-SDK-2.0)）：

- **+X**：指向相机**右侧**
- **+Y**：指向**下**方
- **+Z**：指向**前**方（深度方向）
- 原点位于左相机光学中心

**与 OpenCV 关系**：✅ 完全兼容 OpenCV pinhole 模型（X 右 / Y 下 / Z 前），可直接对接 OpenCV 矩阵。

**相机朝下安装**会让 Y 方向反过来；放在机器人车体上时，**通常需要 RPY 旋转矩阵补偿**。

## 3. 加速度计静止读数（最常被问的坑）

```
静止平放
       +Z（向前）
        ↑
        |
        ●  ←  D435i 朝向
       /
      ↓ +Y（向下）
```

**重力方向是 -Y**（向下为正，重力反向为 -9.8）。

**静止时加速度计读数**：

```
ax = 0
ay = -9.8   ← 注意是负号！因为加速度计测"惯性反作用力"而非重力
az = 0
```

> 来自 librealsense 官方文档：
> "the accelerometer is an inertial sensor and it measures inertial force... the resisting force aims up to the ceiling, and according to the coordinate system the positive Y-axis looks 'down' and therefore the actual reading is **-9.8**"

**坑点**：

- 如果你把 D435i 朝上安装，ay 变成 +9.8
- 如果把 D435i 倒过来（板子朝下），ay 仍然读 -9.8（重力相对于世界永远是向下的，但坐标系跟着相机翻板了）

**检测静止是否正确**：

```python
import pyrealsense2 as rs
import numpy as np

pipe = rs.pipeline()
cfg = rs.config()
cfg.enable_stream(rs.stream.accel)
pipe.start(cfg)

for _ in range(100):
    f = pipe.wait_for_frames()
    accel = f.first_or_default(rs.stream.accel).as_motion_frame().get_motion_data()
    a = np.array([accel.x, accel.y, accel.z])
    print(np.linalg.norm(a))  # 应该 ≈ 9.8
```

## 4. 陀螺仪约定

陀螺仪读数是正向旋转遵循右手定则：

- **gx > 0**：绕 X 轴正向旋转（向右翻滚）
- **gy > 0**：绕 Y 轴正向旋转（向右偏航）
- **gz > 0**：绕 Z 轴正向旋转（向下俯视逆时针）

单位：rad/s（SDK 默认），或 °/s（按需换算）。

## 5. 外参（深度 ↔ IMU）

D435i 的 **深度坐标系 ↔ IMU 坐标系** 的刚体变换**在出厂时根据机械图纸预先计算并烧写**，**不可修改**。

外参可在以下位置读到：

```python
# Python
import pyrealsense2 as rs
pipe = rs.pipeline()
cfg = rs.config()
cfg.enable_stream(rs.stream.accel)
cfg.enable_stream(rs.stream.gyro)
pipe.start(cfg)
profile = pipe.get_active_profile()

# 列出所有外参
for from_stream, to_stream in [
    (rs.stream.depth, rs.stream.accel),
    (rs.stream.depth, rs.stream.gyro),
    (rs.stream.color, rs.stream.accel),
]:
    extr = profile.get_extrinsics(from_stream, to_stream)
    print(f"{from_stream} -> {to_stream}: rotation={extr.rotation}, translation={extr.translation}")
```

输出示例：

```
depth -> accel: rotation=[0.707, 0, -0.707, 0, 1, 0, 0.707, 0, 0.707], translation=[-0.007, 0.005, 0.011]
depth -> gyro:  rotation=[0.707, 0, -0.707, 0, 1, 0, 0.707, 0, 0.707], translation=[-0.007, 0.005, 0.011]
color -> accel: rotation=[1, 0, 0, 0, 1, 0, 0, 0, 1], translation=[-0.015, 0, 0]
```

**翻译**：

- **depth → accel/gyro**：旋转 90°绕 Y（让 IMU 坐标系与深度坐标系对齐，因为 BMI055 物理朝向与左相机不一致）
- **translation**：物理偏移（米），约 1cm 量级
- **color → accel**：基本只平移，旋转为单位阵（RGB 摄像头物理朝向与深度对齐）

## 6. 跨 SDK 的坐标系差异

| 坐标系 | 主流约定 | D435i |
|--------|---------|-------|
| OpenCV | X 右 / Y 下 / Z 前 | ✅ 同 |
| ROS REP-103 | X 前 / Y 左 / Z 上 | ❌ 需要转换 |
| OpenGL | X 右 / Y 上 / Z 后 | ❌ 需要转换 |
| ROS camera_optical_frame | X 右 / Y 下 / Z 前 | ✅ 同 OpenCV |
| ROS base_link | X 前 / Y 左 / Z 上 | ❌ |

**ROS 用户提示**：

- `realsense2_camera` 发布的话题 frame_id 默认为 `camera_*_frame`，**已经是 OpenCV 约定**
- 转 `base_link` 时请用 `robot_state_publisher` 或 `tf2_static_transform_publisher` 提供 TF

## 9. 常见坐标系问题排查

| 现象 | 原因 |
|-----|------|
| IMU 静止读数是 +9.8 而非 -9.8 | 相机上下颠倒安装，Y 轴反向 |
| 点云在 RViz 里"翻转"了 | 用 ROS REP-103 而非 camera_optical_frame 渲染 |
| ORB-SLAM3 初始化失败 | TF 树没接通，或者 IMU 内参/外参没传 |
| 手眼标定误差大 | 没考虑 D435i 的 RGB 与深度视场角差异 |
