# 多相机同步

> 多 D435i 协同工作时，时戳与触发是关键。本页汇总硬件同步、软件同步、ROS 多机示例。

## 1. 为什么需要同步

多个 D435i 同时工作时：

- **不同步**：每台相机用自己的时钟，时间基准不一致 → 融合数据失败
- **同步**：所有相机共享同一时基，帧时间戳可对齐 → 可融合 3D 重建 / 多视角拼接

## 2. 同步方案对比

| 方案 | 精度 | 复杂度 | 适用 |
|------|------|--------|------|
| 硬件触发 | ±1 ms | 高（需接线） | 多机立体 / 拼接 |
| 软件触发（host 时间戳） | ±10 ms | 低 | 单机多视角勉强可用 |
| ROS ApproximateTime 同步 | ±100 ms | 中 | ROS2 松耦合 |
| ROS message_filters exact sync | ±1 ms | 低 | 同机多相机 |

## 3. 硬件触发同步

### 3.1 引脚定义

D435i 主板上预留了 **GPIO 同步引脚**（藏在内部，需要拆壳）：

```
D435i 主板（型号 V2479）
┌────────────────┐
│  USB-C  │ IMU │
│         │ BMI │
│   ASIC  │ 055 │
│         │     │
│  [SYNC] │     │   ← SYNC IN / SYNC OUT 引脚
└────────────────┘
```

官方文档（librealsense multi-camera.md）描述了同步协议，但**实际接线需要拆主板**，社区方案用 **SYNC 引脚交叉连接**：

- **主机** D435i 的 SYNC OUT → **从机** D435i 的 SYNC IN
- 所有从机共享主机的时钟

### 3.2 librealsense multi-camera 工具

```cpp
#include <librealsense2/rs.hpp>

// 启用硬件同步
rs2::context ctx;
auto devices = ctx.query_devices();
for (auto&& dev : devices) {
    dev.set_int_option(rs2_option::RS2_OPTION_INTER_CAM_SYNC_MODE, 
                       RS2_INTER_CAM_SYNC_MODE_HW);
}
```

⚠️ **警告**：硬件同步是进阶功能，官方支持不完善，建议：

- 多机方案：直接用 **ROS2 的 multi_camera_launch.py**（软件时间戳同步）
- 立体方案：用外部触发器（如 Arduino + GPIO）

### 3.3 硬件同步开源方案

社区项目 [librealsense/issues/8558](https://github.com/IntelRealSense/librealsense/issues/8558) 提供了完整的多机同步方案：

```python
# 伪代码
import pyrealsense2 as rs

ctx = rs.context()
devices = ctx.query_devices()

# 第一台作为 master
master = devices[0]
master.hardware_reset()

# 其余作为 slave
for i, dev in enumerate(devices[1:]):
    # 发送 trigger 信号给 slave
    pass
```

## 4. ROS2 多机同步（推荐入门方案）

`realsense2_camera` 提供了官方 multi-camera 启动文件。

### 4.1 单 USB 主机、多相机

```bash
# ROS2 自带 launch
ros2 launch realsense2_camera rs_multi_camera_launch.py \
    camera_name1:=cam_left \
    camera_name2:=cam_right \
    camera1.serial_no:=213722067000 . \
    camera2.serial_no:=213722068000
```

**前提**：

- USB 带宽足够（USB 3.0 + HUB）
- 每台相机的 serial_number 不同（用 `rs-enumerate-devices` 查看）

### 4.2 同步精度

| 配置 | 帧时戳偏差 |
|------|----------|
| 单机双相机（USB HUB） | ±5 ms |
| 双机独立 USB | ±20 ms（依赖 host 时钟） |
| 硬件同步 | ±1 ms |

### 4.3 硬件同步 ROS launch

```bash
# rs_multi_camera_launch_sync.py（同步版本）
ros2 launch realsense2_camera rs_multi_camera_launch_sync.py \
    camera_name1:=cam_left \
    camera_name2:=cam_right
```

`rs_multi_camera_launch_sync.py` 使用 `message_filters` 的 ApproximateTime 做软件同步。

## 5. 时间戳对齐原理

### 5.1 设备时钟（device time）

- 每台 D435i 有独立硬件时钟（从 USB 上电开始计数）
- librealsense SDK 提供 `frame.get_timestamp()` 返回该时钟时间（毫秒）
- 不同设备的 device time **不可直接比较**

### 5.2 Host 时间（host time）

- USB 驱动收到数据包后打 host 时间戳
- ROS2 默认使用 host 时间
- 所有相机的 host time 是同一时基，**可直接比较**

### 5.3 ROS2 时间策略

在 `rs_launch.py` 设置：

```yaml
# ros2 launch realsense2_camera rs_launch.py \
#   depth_module.profile:=640x480x30 \
#   pointcloud.enable:=true
```

ROS2 节点启动后会自动同步 device_time → ROS2 /clock。多相机时**优先用 ROS2 time 而非 device_time**。

## 6. message_filters 同步示例

```python
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import Image, Imu
from message_filters import Subscriber, ApproximateTimeSynchronizer

class SyncNode(Node):
    def __init__(self):
        super().__init__('sync_node')
        
        # 多相机订阅
        self.depth_sub1 = Subscriber(self, Image, '/cam_left/depth/image_rect_raw')
        self.rgb_sub1   = Subscriber(self, Image, '/cam_left/color/image_raw')
        self.depth_sub2 = Subscriber(self, Image, '/cam_right/depth/image_rect_raw')
        self.rgb_sub2   = Subscriber(self, Image, '/cam_right/color/image_raw')
        
        # 同步器（容差 50ms）
        self.sync = ApproximateTimeSynchronizer(
            [self.depth_sub1, self.rgb_sub1, self.depth_sub2, self.rgb_sub2],
            queue_size=10,
            slop=0.05
        )
        self.sync.registerCallback(self.sync_callback)
    
    def sync_callback(self, d1, r1, d2, r2):
        # 同步回调：d1 与 d2 时间戳接近
        self.get_logger().info(f'Sync: {d1.header.stamp.sec}.{d1.nsec}')
```

## 7. 多机硬件同步实战

### 7.1 双 D435i 立体方案

```
       主机                          从机
   ┌─────────┐                  ┌─────────┐
   │ D435i 1 │ ←───USB 3.0──────│         │
   │         │                  │         │
   │  SYNC   │ ───trigger─────▶ │  SYNC   │
   │  OUT    │                  │  IN     │
   └─────────┘                  └─────────┘
       │                             │
       └─── 单 PC 通过 USB HUB 连接 ──┘
```

**典型用途**：远距离立体深度（基线 > 50mm），可测距 10m+

### 7.2 四 D435i 360° 环视

```
                前
                ↑
        左 ── ● ── 右
                ↓
                后

每台 D435i 共享一个 PC 的 host time
ROS2 用 ApproximateTimeSynchronizer 同步
```

**精度**：单 PC 多 USB → ±5 ms；多 PC + 网络 → ±20 ms（需 NTP）。

## 8. 多相机在线标定

### 8.1 相机-相机外参

```bash
# 安装 Kalibr
sudo apt install ros-<dist>-kalibr

# 准备标定板
ros2 run kalibr kalibr_calibrate_cameras \
    --target april_6x6.yaml \
    --bag cam1_cam2_calib.bag \
    --models pinhole-radtan pinhole-radtan \
    --topics /cam_left/color /cam_right/color
```

输出 `camchain.yaml`，包含两相机外参。

### 8.2 相机-IMU 外参

```bash
ros2 run kalibr kalibr_calibrate_imu_camera \
    --target april_6x6.yaml \
    --bag cam_imu_calib.bag \
    --cam camchain.yaml \
    --imu imu.yaml
```

输出 `camchain-imu.yaml`，含相机-IMU 旋转/平移 + 时延。

## 9. 同步质量监控

```bash
# 看每个话题的发布频率
ros2 topic hz /cam_left/depth/image_rect_raw
ros2 topic hz /cam_right/depth/image_rect_raw

# 看话题延迟（用 tf2 echo 看 base_link -> camera_frame 时延）
ros2 run tf2_tools view_frames
```

如果两台相机延迟差异 > 50ms，检查：

- USB 是否同时在 3.0
- 主机 CPU 是否饱和
- ROS2 QoS 是否合理（depth image 用 RELIABLE）

## 10. 常见问题

| 问题 | 排查 |
|------|------|
| 两台相机帧不同步 | 检查 serial_number 是否正确、是否都接 USB 3.0 |
| ApproximateTime 找不到匹配 | slop 太小（试 0.1s）|
| 多机时间差大 | 配置 NTP / chrony |
| 硬件同步没反应 | 拆壳接 SYNC 引脚，参考 Intel 官方文档 |
| 同步后点云融合失败 | 外参不对，重跑 Kalibr |
