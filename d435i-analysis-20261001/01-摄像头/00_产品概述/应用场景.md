# D435i 典型应用场景

> 从社区实践与官方推荐案例出发，归纳 D435i 适合的 5 类应用。

## 场景一：机器人室内 SLAM

**为什么 D435i**：宽视角（87°）+ IMU + 双目 → 紧耦合 VIO/RGBD-SLAM 的"视觉里程计 + 后端优化"链路非常成熟。

**典型方案**：

| 方案 | 模式 | 优点 | 限制 |
|-----|------|------|------|
| **RTAB-Map** | RGB-D + 闭环 | 全开源、ROS 原生集成、闭环强 | 大场景需调内存 |
| **ORB-SLAM3** | Mono-Inertial / Stereo-Inertial | 视觉里程计精度高 | ROS2 集成偏折腾 |
| **Cartographer** | 3D SLAM | Google 出品，2D/3D 通用 | 调参复杂 |
| **VINS-Fusion** | Mono / Stereo + IMU | 紧耦合，精度好 | 配置门槛高 |

**集成示例**：直接用 `realsense2_camera` 启动 → RTAB-Map 订阅 `/camera/depth_registered/points` 与 `/camera/imu`。

> 详细教程见 [04_应用场景/SLAM建图.md](../04_应用场景/SLAM建图.md)

## 场景二：机械臂视觉抓取

**为什么 D435i**：0.3-3 m 范围正好覆盖工作台；点云 + RGB 配准后可直接用于 6DoF 抓取位姿估计。

**典型流程**：

```
RGB 图像 → YOLO/GroundingDINO 检测目标 2D bbox
                  ↓
深度图 → 取 bbox 内点云 → 计算 3D 中心
                  ↓
手眼标定矩阵 → 转换到机械臂基坐标系
                  ↓
MoveIt! 规划抓取轨迹
```

**典型方案**：

| 库 | 用途 |
|----|------|
| `easy_grasp` / `graspnet` | 6DoF 抓取位姿 |
| `detectron2` / `yolov8` | 目标检测 |
| `open3d` | 点云处理 |
| `pyrealsense2` | 相机 SDK |

## 场景三：物体测距与体积估算

**为什么 D435i**：USB 供电、即插即用；点云 API 简洁。

**典型用法**：

```python
import pyrealsense2 as rs

pipeline = rs.pipeline()
config = rs.config()
config.enable_stream(rs.stream.depth, 640, 480, rs.format.z16, 30)
pipeline.start(config)

while True:
    frames = pipeline.wait_for_frames()
    depth = frames.get_depth_frame()
    
    # 测量 (x, y) 像素点的距离（米）
    dist_meters = depth.get_distance(x, y)
    
    # 获取 (x, y) 处的 3D 坐标
    point_3d = rs.rs2_deproject_pixel_to_point(
        depth.get_profile().as_video_stream_profile().get_intrinsics(),
        [x, y],
        dist_meters
    )
    # point_3d = [X, Y, Z] 米
```

完整代码见 [02_SDK与编程/示例代码.md](../02_SDK与编程/示例代码.md)。

## 场景四：RGB-D 数据采集

**为什么 D435i**：ROS 录制 bag 一步到位；SDK 自带 `rs-record` / `rs-convert`。

**采集方案对比**：

| 方案 | 输出 | 用途 |
|-----|------|------|
| ROS2 bag (`.mcap` / `.db3`) | 全部话题 | ROS 回放训练 |
| `rs-record -> rosbag` | 同步录制 | 离线回灌到 ROS |
| `rs-convert` → PNG + JSON | 离线格式 | 算法训练数据集 |
| `pyrealsense2` 自定义 | 灵活 | 私有数据格式 |

**录制示例**：

```bash
# ROS2 录制
ros2 bag record /camera/depth/image_rect_raw \
                /camera/color/image_raw \
                /camera/imu

# librealsense 直接录制
rs-record -d  # 默认输出 realsense.bag
```

## 场景五：多相机阵列（立体 / 拼接）

**为什么 D435i**：硬件同步引脚支持外部触发；时戳统一。

**两种模式**：

1. **硬件同步（推荐）**：通过 GPIO 引脚连接，多机共享时钟
2. **软件同步**：依赖 host 时间戳，精度差

**典型用法**：

- 双 D435i → 立体深度（> 6m 远距离场景）
- 四 D435i 环视 → 360° 室内建图
- D435i + D455 → 远近覆盖混合感知

> 详见 [04_应用场景/多相机阵列.md](../04_应用场景/多相机阵列.md)

## 不适合的场景

| 场景 | 原因 | 替代方案 |
|-----|------|---------|
| 户外强日光 | 红外投射器被淹没 | D405（被动双目）/ 雷达 |
| 透明 / 镜面物体 | 红外无法穿透 | 结构光 + ToF 融合方案 |
| 6m+ 远距离 | 基线短 + 投射器功率 | D455 / Livox Mid-360 |
| 高速运动（> 5 m/s） | 全局快门可应付但 IMU 噪声差 | 高端 VI-Sensor |
| 防爆 / 防水 | 非工业防护等级 | 工业级 GigE 相机 |

## 选型决策树

```
你的应用是什么？
├── 室内 SLAM ─────────────→ D435i + RTAB-Map ✅
├── 机械臂抓取 ────────────→ D435i + YOLO + GraspNet ✅
├── 室内测距 ──────────────→ D435i ✅
├── 户外 / 远距 ───────────→ D455 / Livox
├── 高精度小物体 ──────────→ D405
└── 多机阵列 ──────────────→ 多个 D435i + 硬件触发
```
