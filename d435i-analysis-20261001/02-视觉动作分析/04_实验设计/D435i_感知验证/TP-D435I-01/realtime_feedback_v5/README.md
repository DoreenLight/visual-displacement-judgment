## 本轮实现

### 手动删除与恢复

- 每个已保存试次有“删除试次”。确认后从本机训练列表、进度统计、下载可见记录和后续候选选样中移除。
- “已删除试次”中可恢复。删除依据本版本[deleted_trials.json]文件（首次实际删除时才创建），是覆盖层，不修改旧原始文件、旧索引和冻结报告。
- 训练过程中新增“结束并删除本次”：正常完成保存和四包导出，再标记删除；保存出错不会伪装为成功删除。
- 原始视频/深度/派生文件仍在本地，便于误删恢复，不释放磁盘空间。本功能不是永久擦除。当前没有工具删除用户的任何真实试次。
- 后续分析选择应使用`TrialManagement.active()`，同时遵守各旧版本的既有排除清单；历史冻结分析仍反映其当时输入，不重写成新选择结论。
- 服务只接受已知run_id，不接受用户路径；删除/恢复串行处理，正在保存时禁止操作。旧v3、v4、新v5的试次统一展示，新数据与输出另存v5版本。

### 腕屈伸与桡偏/尺偏

1. 手部深度由大7×7混合窗口改为3×3或5×5当前帧中心连通深度簇：要求中心真实有深度、邻域支持足够且深度一致。不会用背景、旧帧或空洞填补值伪装测量。人体大点仍沿用原方法。
2. 腕角只依赖可见的肘、腕及手部点和前臂几何，不再要求肩点存在。肩点丢失时肩肘参与状态未知，但腕角仍可独立观测。真正前臂/手部缺失时仍无效。
3. 中立腕零位由单帧改为至少1秒、至少12帧稳定手部点的中位参考；手部位置P95变化须≤15mm，指示用户手腕中立、手背及指根可见。这是稳定参考，不是解剖真值。
4. FE/RU/回转开始前要求手参考已建立；每次结束后清除旧基线和手零位，避免下一试次沿用过期标定。身体基线约3秒，随后手零位约1秒，总体需按页面提示静止就位。
5. 保留无效值、原始测量、候选角和平滑输出。显示平滑不能承诺绝对角度准确，也不能解决前臂旋前/旋后未观测的问题。

### 动作完成与肩肘参与分开

- 查明旧版本肩肘报警本身并不直接阻断计数；主要问题是腕角依赖肩点，以及任何一帧角度缺失都重置半周期。
- 新版FE/RU允许从任意一侧起步。有效角度到一侧→另一侧→回到起始侧才算完整往返；只做半周期不计数。
- 短暂缺测≤250ms保留部分周期，不生成或显示补造角度；超过250ms、明显跳变、暂停或基线切换仍重置。复合回转同样容忍短缺测，但角平面必须完整转过一周，回到零点或过大相位跳变会重置。
- 肩肘报警仅作为参与提示，不把有参与的一次动作自动判为未完成。长时间手部不可观测仍不能靠放宽规则可靠计数。
- FE/RU可以开始前调整参考计数单侧门槛，范围5–30°；默认FE15°、RU10°。降低门槛会增加把抖动当动作的风险，这不是临床合格幅度或安全处方。应用后重置部分周期，训练中不允许更改。
- “完成候选周期数”与“动作质量合格数”分开，当前不宣称临床动作质量已验证。回转方向仍由操作阶段标记，未验证自动真实方向。

## 怎样才能获得稳定且准确的两个角度

先验证新版重新校准后的可用率、静止角度波动与人工周期一致性。拍摄时尽量让右肘、前臂、手背和指根在视野中，前臂有支撑，保持实际运动轴可观测，避免在弯腕过程中设零。

当前固定中立掌平面无法独立观测前臂旋前/旋后，深度表面点也不是骨段坐标系。若目标是稳定且可量化准确的FE/RU，需要可观测的前臂与手刚体方向参考（例如经标定的固定标志或独立角度参考）以及同步误差验证；不能靠更强滤波或更宽阈值保证准确。

官方来源：[RealSense深度后处理说明](https://dev.realsenseai.com/docs/depth-post-processing-for-intel-realsense-depth-camera-d400-series/)解释时间平滑可能带来运动伪影；[MediaPipe手关键点说明](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/android)中的world landmarks是模型输出，不能替代经验证的RGB-D骨段角度。
