## 1 每个点目前达到多少毫米？

以下是六个静止S1/S2试次逐试次计算后取范围。P95=有效三维点相对该试次中位位置的距离的第95百分位。它包括人体微动、RGB关键点定位变化、深度噪声、表面采样与配准效应；既不是±准确度，也不是最大误差。无效点不计入P95，另有有效率记录，不能仅按有效点的窄波动说明遮挡稳定。

| 观测点 | 静止位置波动P95范围 mm |
|---|---:|
| 右肩 | 11.3–17.5 |
| 右肘 | 7.7–23.4 |
| 右腕（姿态模型） | 4.3–36.3 |
| 手腕（手部模型） | 3.2–8.2 |
| 食指根部 | 4.1–210.1 |
| 中指根部 | 2.1–15.2 |
| 小指根部 | 2.2–5.1 |

不能据此宣布任一点准确到1mm、5mm或10mm。相机当前深度数值步长约1mm，是量化尺度，不等于测量误差。厂商D435/D435i深度Z准确性规格为2m处<2%（数值对应40mm）；这是出厂深度指标，不是人体关节中心XYZ准确度，也不能按比例外推本次0.6–1.3m场景。

出处：[RealSense官方规格](https://www.realsenseai.com/compare-depth-cameras/)。本地来源：[逐点指标](../offline_reanalysis_v1/analysis_20261001_v1/joint_metrics.csv)、[离线报告](../offline_reanalysis_v1/REPORT.md)。

### 原因能否分清？

| 环节 | 已有证据与判断 | 下一步验证 |
|---|---|---|
| 设备/成像 | FE边缘深度散布、空深度是实际测量限制；当前不够信息判断相机标定误差。软件7×7取样也影响混合深度，不能全归硬件。 | 刚性平面固定距离，分别测中心/边缘深度与RGB-D对齐；与独立距离比较。 |
| 拍摄/操作 | 手背/指根遮挡、快速复合动作和肩肘大幅运动伴随失效；静止试次仍可能有微动。指令标签不能证明实际姿态符合要求。 | 固定前臂、减少遮挡、手部够大且全在视野中；重复相同动作，记录摆位。 |
| 实时程序 | 同一批原始帧离线组合有效率由57.8%变94.8%，说明实时处理/覆盖存在贡献，不能把36.9个百分点全归推理精度改善。两个静止试次旧基线产生约99.3%报警；另一个握柄试次手点可见但缺手参考角无法输出。 | 新试次重新建立中立基线、改善分析覆盖、验证手点目标所属、修正轴/零位/计数，再做同段对照。 |
| 定义 | 当前是在RGB关节点附近取深度表面点，皮肤表面不等于解剖关节中心；单纯滤波不能修复定义偏差。 | 解剖标志/刚体参考、前臂与手坐标系标定，独立角度/三维参考。 |

结论：已证明存在软件问题，拍摄可见性也有影响；目前无法把总误差按百分比分配给设备、操作和程序。

## 2 转多少度才能自动计数？

这是当前源码的触发规则，不是准确识别的性能承诺：

| 动作 | 原计划目标 | 当前自动规则 |
|---|---|---|
| 腕屈伸 FE | 中立位两侧约−30°至+30°，每往返2–3秒，共10次 | 先候选角≥+15°，再≤−15°，再≥+15°才完成一个周期；最小跨越幅度30°峰峰值。第一半个往返不构成完整周期。 |
| 桡偏/尺偏 RU | 中立位两侧约−20°至+20°，每往返2–3秒，共10次 | 候选角≥+10°→≤−10°→≥+10°，最小跨越20°峰峰值。 |
| 复合回转 | 手相对前臂依次经历屈伸及左右偏，顺时针5圈、逆时针5圈 | FE/RU二维角平面绕中立零点一周，相位累计约360°；每帧角向量半径至少6°，相邻相位跳变不超过90°。方向由人为切换阶段，旧计数规则不能验证实际转向。 |

回转的360°是FE/RU二维轨迹的相位周数，不是手腕绕一根轴转360°。目前没有已验证的“回转半径多少就必然计数”标准，不应为了满足算法扩大人体动作。使用现有舒适幅度，明确中立位和运动平面后测试。

只达到动作幅度不保证计数：必须角度有效、零位正确、通道对应正确且连续（长缺口重置半周期）。已录清楚RU片段候选RU为−69.6°至−14.4°，即使有周期变化也永远过不了+10°，所以计数为0。应排查轴/零位与实际运动对应，而不是要求受试者继续用更大幅度解决软件问题。

当前v4增加显示与延迟测量，FE/RU估计和计数仍使用旧工程规则，尚未宣称修复准确计数。可继续人工确认次数用于后续对照。

## 3 曲线是不是标准生物力学测量？

本版显示工程估计，三条主要曲线定义明确但不具备ISB标准完整测量条件：

- 蓝色：肩→肘向量相对中立基线的夹角，反映上臂摆动。没有胸廓坐标系与肩胛/肱骨解剖标定，不能等同肩关节屈伸/外展/内外旋，躯干运动会混入。
- 红色：180°减去肩−肘−腕三点夹角，是肘屈曲几何估计。当前三点为表面估计，不能代替经校准的骨段坐标系。
- 黑色/绿色：手中指根与手腕构成手方向，相对前臂和固定中立掌法向估计FE/RU。前臂旋前旋后未独立观测，腕运动轴及零位仍需验证；正式FE/RU测量列仍无效。

要得到标准生物力学坐标曲线，需要胸廓/上臂/前臂/手坐标系、解剖标志或可验证替代、旋转顺序/符号和中立位标定，随后用独立参考检验。见[ISB肩肘腕推荐](https://media.isbweb.org/images/documents/standards/Wu%20et%20al%20J%20Biomech%2038%20%282005%29%20981%E2%80%93992.pdf)。

## 4 延迟的测量口径

### 已实现的收帧→浏览器绘制

- t_receive：SDK返回原始RGB-D帧后立即记录电脑单调时间，在深度对齐前；包含后续对齐、复制、等待分析、模型、角度、JPEG、接口、传输和浏览器解码/绘制回调。
- 页面调用/clock进行5次往返，选择RTT最小的中点估计，将浏览器performance.now映射到电脑单调时钟；±RTT/2作为往返范围指标，仅是软件时钟估计，不是传感器硬件同步验证。
- 相机图像解码并设置，图线绘制后经过两次requestAnimationFrame记录t_draw。延迟=t_draw_est−t_receive。界面显示当前值及最近200次P50/P95；每30秒重新估计时钟，后台页不统计。
- 这是浏览器绘制回调估计，不能保证屏幕像素真正点亮的时刻。图线软件样本时刻仍是原始帧的收帧时刻，不把结果时刻当动作时刻。

### 尚未测得的真实动作→屏幕

缺少相机曝光到主机的已验证时钟映射及物理显示测量，因此当前不能报真实总延迟多少毫秒。它还包括采样等待/曝光、相机内部与USB，以及显示刷新。30fps的帧间隔约33.3ms，不代表总延迟只有33.3ms。

曲线100ms时间常数平滑额外造成动态相位滞后，不能直接当固定100ms延迟。腕候选角还使用上游EMA alpha=.55，其影响依实际分析频率变化。代偿报警另有180ms持续条件，不能把报警延迟当曲线延迟。

已用实际相机数据完成60秒自动化浏览器观测：[实测统计](real_latency_check.json)、[733次测量CSV](measured_browser_latency.csv)。浏览器软件绘制延迟P50约90ms、P95约120ms，时钟中点估计范围约±1ms。此结果不包括平滑动态滞后和物理显示刷新，且未开启录制。下一步在用户实际前台窗口和录制保存负载下各重复观测。若要验证真正动作→屏幕，可用一段同时拍到测试者和屏幕的高帧率录像，对明确同一事件逐帧比较；需要定义是运动起始还是峰值，保留原片与帧率证据。
