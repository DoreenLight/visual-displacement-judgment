## 2. 统一技术口径

1. **在役硬件统一为 D435i。** 相机内置 IMU 测量相机本体运动，不是固定相机下的人体腕关节运动；不把内置 IMU 设为四包必需数据源。
2. **真实深度坐标与模型估计坐标分开。** MediaPipe `world landmarks` 是以髋部中心为原点的模型估计，不是深度反投影测量。两者分别标注 `real_rgbd`、`model_rgb`，不得混成一套“毫米级实测”。
3. **稳定性与准确性分开。** 自身均值附近的标准差不是对真值的误差；准确性必须有独立、同步且经过标定的参考。
4. **腕点位移与腕关节活动度分开。** 屈伸时腕部点可能基本不动。角度测量须包含手部相对于前臂的姿态，不能用前臂长度充当腕屈伸半径。
5. **肩肘代偿按任务定义。** 本版目标是肩部、肘部及二者共同参与；不把前臂旋转代偿自动扩展为第五个任务或本版验收项。
6. **单相机能力按可见性验证。** 不预先宣称单相机只能二分类，也不宣称45°视角一定足够。不可观测时输出 `unknown`，必要的布局变更先确认。
7. **原 CI 的主要问题是语义。** 同单位位移比在 epsilon 具有长度单位时无量纲；腕点位移接近零、周期回起点和代偿带动腕移动会破坏其解释。不得将其直接作为控制量。
8. **先离线评价，再在线监督。** 本版不交付已获授权的自适应控制器，不以运动轨迹推断患者主动发力或临床疗效。

## 3. 通用实验条件与安全边界

- 初始采集配置：室内稳定光照、坐姿、深度 `848×480@30 fps` 或 `640×480@30 fps`，RGB 实际模式由设备支持情况确定并记录。
- 初始工作距离：1.0～1.5 m；初始前侧方约45°。这些是需要验证的候选条件，不是性能保证。
- 开始录制前确认肩、肘、腕及需要的手部参考可见；真实握柄状态也必须检查，不以空手可见替代。
- 通电后记录预热、曝光与投射器设置；不得把固定预热时长写成已验证事实。
- 首轮只做经授权的健康志愿者工程验证。临床患者实验需独立伦理、知情同意和治疗师批准。
- 受试者疼痛、疲劳、不适，机器人意外运动，或有效性检测持续失败时停止。不得为了凑样本继续。
- 人体原始视频属于敏感数据：使用去标识化 `participant_id`，记录同意与访问权限；不上传公开仓库或网页展示台。
- 原任务中的屈伸±30°、桡偏/尺偏±20°和10次循环仅是健康工程测试候选；以实际安全范围为先。

## 4. 输入、坐标与时间契约：`wrist-rehab/v1`

### 4.1 每次录制必须有 `run.json`

记录 `schema_version`、`run_id`、`task_id`、`attempt_id`、参与者代号、训练侧、session/trial、数据来源类型、采集日期、硬件序列号、固件/SDK/模型版本、RGB/深度真实模式、曝光、内参/畸变/外参、相机布置、标定编号、任务包版本、阈值配置、滤波配置、参考系统与同步方法、实际执行命令及退出码。

同时记录 RGB 与深度帧各自的时间戳和时钟域；主机用单调时钟记录接收/输出时间。跨设备必须有显式时钟映射和同步误差，不能只用 `frame_index/fps` 假定没有丢帧。无法获取的字段使用 `null` 并说明影响，不填造数值。

### 4.2 三维关键点长表：`keypoints.csv`

必需列：

```text
run_id,frame_id,joint_id,t_rgb_device_s,t_depth_device_s,t_host_mono_s,clock_domain,
u_px,v_px,x_raw_m,y_raw_m,z_raw_m,x_filt_m,y_filt_m,z_filt_m,
keypoint_score,visibility,depth_valid,measurement_valid,imputed,
valid_for_analysis,invalid_reason,coord_frame
```

- `joint_id` 至少包含训练侧 `shoulder`、`elbow`、`wrist`；手部点和躯干参考另有明确名称，不能重用 wrist 字段。
- 原始点默认在固定相机的光学坐标系 `camera_color_optical`：X向右、Y向下、Z向前，长度单位米；必须使用配准后数据对应的内参及畸变模型。
- 对躯干或机器人坐标变换另存变换矩阵、标定编号和结果，不覆盖原始相机坐标。显示用毫米/Three.js 坐标只属于派生表示。
- 置信度和可见性不保证是经校准概率；保留模型定义与阈值。深度无效或点不可靠时坐标为 `NaN`，附原因，不填零或上一帧冒充实测。
- `imputed=true` 的点不计入真实有效帧比例或参考误差。本版默认只允许其用于明确标记的可视化，不用于正式性能验收。
- 原始和滤波后指标分别报告；在线因果滤波必须报告延迟。使用未来帧的离线零相位处理不能宣称可直接实时使用。

### 4.3 下游表

| 所属包 | 文件 | 最小内容 |
|---|---|---|
| TP-02 | `wrist_kinematics.csv` | run/frame/time，wrist/hand参考点位置，`theta_fe_deg`、`theta_ru_deg`，位置/角度各自有效性，标定与坐标约定 |
| TP-03 | `compensation.csv` | 肩/肘特征，两个独立检测通道，组合状态，置信信息，unknown原因，人工标签来源与事件时间 |
| TP-04 | `quality.csv` | 窗口/周期标识，完成度、代偿、平滑度、可靠性及各自有效性，参数版本，输出时间/延迟 |

角度不存在或不可观测时填 `NaN` 和状态，不用0°冒充缺失。所有表以 `run_id`、真实时间戳关联，不能单靠行号对齐。

输入身份冻结分两层：

## 6. 验收阈值管理

四包给出的数值均为**候选工程验收目标**，不是厂家承诺、既有实测结果或临床正常值。用于针对明确的大幅代偿和慢速训练的首轮可行性验证。

- 执行前冻结阈值、参与者/试次数量、任务范围和参考系统；默认采用各包候选值，改变必须说明并修订配置。
- 分别报告每个参与者、关节和条件，不以跨人平均掩盖单人持续失效。
- 不在看到测试集后调阈值，再用同一测试集宣称通过。调参数据和独立评估数据按受试者或session隔离。
- 最少样本量不是临床效力保证；先做单人连通性，再制定跨人、跨次的工程验证规模及其限制。
- 没有独立参考时，可以判定“能采集/重复性达到目标”，准确性与角度定量能力的验收项必须是 `BLOCKED`，不能写总体全项 `PASS`。
