> **所属**：ViKiT 组件 ①（source language 编码器）

> **下游**：`02 · Spatio-Temporal Transformer Encoder`

## 1. 设计目标与不可替代性

### 1.1 目标

把「普通 ViT 的规则网格 patches」替换为**按人体运动链切分的视觉 token**，使 token 在**表征层**就携带解剖语义。

输出：

$$V_t = [\,v_{t,\text{hip}},\ v_{t,\text{thigh}},\ v_{t,\text{knee}},\ v_{t,\text{shank}},\ v_{t,\text{ankle}},\ \ldots\,],\qquad v_{t,i}\in\mathbb{R}^{d}$$

### 1.2 为什么这是 ViKiT 最硬的一条差异（必须写进 paper）

对照已掌握的两个竞争对手（详见 `../../01_参考论文/`）：

| 方法 | 空间表征 | 是否显式 token | 是否解剖语义 |
|---|---|---|---|
| **Chao 2026 Measurement**（直接竞品） | CNN 特征图 | ❌ 无显式 token 化 | ❌ CNN patch 无解剖标签 |
| **Jamsrandorj 2023 EMBC**（同团队，真实全文已获取） | **ResNet18** 特征 | ❌ 特征序列直连 Transformer | ❌ 无解剖语义 |
| **Wei 2026 JBHI**（种子论文，sEMG 域） | 3DCNN，按**肌肉解剖 + 电极位置**组织感受野 | ⚠️ 隐式 | ✅ 但注入的是**肌肉**模态 |
| **ViKiT（我方）** | 按**人体运动链**切分的视觉 token | ✅ **显式** | ✅ 注入的是**关节链**模态 |

> **一句话差异**：竞品的 Transformer 吃到的是**无语义的 CNN 特征序列**；
> ViKiT 吃到的是**以解剖单元为符号的句子**。这是**表征层的结构差异，不是命名差异**。

### 1.3 与前身工作的关系（诚实表述）

思路来源：Wei 2026 用「muscle anatomy informed representation」指导 sEMG 端的 3D CNN。
**我方把「解剖先验注入」从肌肉模态迁移到关节链模态、从卷积感受野迁移到 token 化。**
→ 这是**迁移 + 结构化**，不是首创。paper 中必须承认（见 §7 风险 R4）。

## 2. 结构设计

### 2.1 三种切分方案（按优先级，需 A/B 实测）

| 方案 | 机制 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| **S1 · 关键点引导 attention** | 用现成 2D 关键点（如 ViTPose / MediaPipe）定义 region 中心，按距离做 soft assignment | 无需额外标注；关键点检测器已成熟 | 关键点误差会传导；遮挡时失效 | **主方案**（MVP 先跑通） |
| **S2 · 语义分割 mask** | 用人体解析（Human Parsing）得到肢体 mask，按 mask 聚合 patch | 边界更准；遮挡更鲁棒 | 依赖额外模型；跨域泛化未知 | **备选/消融** |
| **S3 · 可学习 soft assignment** | 纯端到端学习每个 patch 归属哪个 anatomy region | 无外部依赖；可能与下游任务最匹配 | 无先验约束，易退化成语义无关的聚类 | **消融对照**（验证"解剖先验是否必要"） |

> ⚠️ **S3 是关键的消融项**：若无解剖先验的 S3 与 S1/S2 表现相当，
> 则"anatomy-aware"这一命名会被审稿人质疑为"没用的归纳偏置"。
> → 这一条已登记为 `../../04_实验设计/Ablation设计.md` 的 **A1（去 anatomy token）**。

### 2.2 Anatomy region 定义（上肢代偿版）

依据本库 `08_三维动作分析展示台/` 已实现的三级代偿分析（腕 → 腕肘 → 腕肘肩）：

| Region ID | 名称 | 对应关节链段 | 临床意义 |
|---|---|---|---|
| `r0` | torso | 躯干（参照系） | 代偿的**近端稳定源** |
| `r1` | shoulder | 肩 | 代偿的**近端发起者** |
| `r2` | upper_arm | 上臂 | 肩-肘耦合载体 |
| `r3` | elbow | 肘 | **中间关节**：既是代偿的受害者也是发起者 |
| `r4` | forearm | 前臂 | 旋前/旋后载体 |
| `r5` | wrist | 腕 | **任务执行端**，代偿的**首要观测点** |
| `r6` | hand | 手 | 任务有效载荷 |
| `r7` | global | 全身上下文 | 补偿失去的全局信息（**必须保留**，见 §4 F3） |

> **`r0` 与 `r7` 是必需的**：只切肢体、不保留躯干与全局上下文，
> 会使"肩部代偿"这类**近端借力**现象无法被观测——因为代偿的证据就藏在躯干与全身的姿态中。

### 2.3 Token 编码器

| 项 | 设计 | 依据 |
|---|---|---|
| 每 region 编码器 | **小型 ViT（ViT-S/16 级别）**，跨 region **共享权重** | 参数效率；region 语义词性相同 |
| 输入分辨率 | 每 region 按 bounding box 裁剪 → resize 到 **112×112** | 与 ViT-S/16 对齐；控制序列长度 |
| Token 维度 $d$ | **256**（基线）／**384**（充分实验） | 与 kinematic vocabulary 维度对齐；见 `04` 的设计 |
| Token 数/帧 | **8**（r0–r7，含 global） | 见 §2.2 |
| 序列长度 $T$ | **81 帧**（≈2.7 s @30 fps，基线） | 见 §4 F5 与 `03` 的选型论证 |
| 位置编码 | **帧号 + region id 双编码**（见 `03`） | region 是序不变集合，帧是有序轴 |

### 2.4 关键点引导的 soft assignment（S1 细节）

```
对每帧 t：
  1. 用外部 2D 关键点检测器取 K 个关键点 p_k = (x_k, y_k, c_k)
  2. 对每个 region r，定义其锚点集合 A_r ⊆ {p_k}
     （例：elbow 的锚点 = {shoulder, elbow, wrist}）
  3. 每个 patch i 对 region r 的归属权重：
       w_{i,r} = softmax_r( -||c_i - c_r||^2 / τ ) · 1[confidence]
     其中 c_i 为 patch 中心，c_r 为 A_r 的加权质心，τ 为温度
  4. token v_{t,r} = Σ_i w_{i,r} · f(patch_i) / Σ_i w_{i,r}
     （f = ViT patch embed + 若干 attention 层）
```

**温度 $\tau$** 是核心超参：
- $\tau \to 0$ ⇒ 硬分配（接近 S2 的 mask 效果）
- $\tau \to \infty$ ⇒ 均匀分配（退化为全局池化，解剖先验消失）
- 建议初值 $\tau = 0.1$，并按 `../../04_实验设计/Ablation设计.md` A1 扫描 $\tau \in \{0.01, 0.05, 0.1, 0.5\}$

## 3. 超参汇总

| 超参 | 基线值 | 搜索范围 | 说明 |
|---|---|---|---|
| ViT backbone | ViT-S/16（共享） | ViT-Ti / ViT-S / ViT-B | 见 §4 F1 |
| 输入分辨率/region | 112×112 | 96 / 112 / 224 | 224 会让显存翻 4 倍 |
| Token 维度 $d$ | 256 | 192 / 256 / 384 | 需与 `04` 的 VQ 码本维度一致 |
| Region 数 | 8 | 6–10（消融 region 粒度） | 去掉 r0/r7 是消融项 |
| 序列长度 $T$ | 81 | 27 / 45 / 81 / 121 | **27 = 直接对标 KIST 的窗口**（见 §4 F5） |
| 分配温度 $\tau$ | 0.1 | 0.01–0.5 | 见 §2.4 |
| 预训练 | ImageNet 或 HMR 2.0 权重 | 随机初始化作对照 | 见 §4 F2 |
| 是否冻结 backbone | 前 5 epoch 冻结，之后解冻 | 全冻 / 全解冻 | 小数据下冻结更稳 |

## 4. 失败模式与对策（必读）

| # | 失败模式 | 症状 | 根因 | 对策 |
|---|---|---|---|---|
| **F1** | **Token 过少导致信息瓶颈** | 训练 loss 降不下去，MAE 高于 CNN baseline | 8 个 token/帧 ≪ CNN 的数百个 patch 特征，信息被压掉 | ① 提高 $d$ 到 384；② 每 region 输出 **多 token**（如 4 个）而非 1 个；③ 加 global token（已含 r7） |
| **F2** | **Backbone 与 token 化目标冲突** | 从 ImageNet 迁移后反而更差 | ImageNet 学的是**物体类别**，与**运动链切分**目标不对齐 | ① 用 HMR 2.0（人体先验）权重替代 ImageNet；② 前 5 epoch 冻结；③ 加弱监督（关键点定位 auxiliary loss） |
| **F3** | **去掉躯干/全局 token 后近端代偿无法观测** | 腕角精度尚可，但"肩代偿"分类指标崩掉 | 代偿证据在躯干与全身姿态里 | **强制保留 r0 与 r7**，并把它作为 region 消融的**下界检验** |
| **F4** | **关键点检测器在遮挡下失效 → token 崩坏** | 遮挡场景指标断崖 | S1 对关键点质量的**硬依赖** | ① fallback 到 S3 的纯可学习分配；② 对低 confidence 关键点做**掩码 + 插值**；③ 训练时随机丢关键点做增强 |
| **F5** | **序列过长导致显存/时序注意力退化** | OOM 或长序列性能反而下降 | 复杂度 $O(T^2)$；且解剖 token 已提供局部性，长 $T$ 收益递减 | ① 基线取 **T=81**；② 长序列用 **windowed attention**；③ 用 T=27 对标 KIST 的短窗结论（见下） |
| **F6** | **跨被试泛化差（过拟合到个人体型）** | 训练集好、测试集差 | token 隐式编码了体型 | ① 严格**按被试划分**（KIST 在 2022 年已这样做，我方可参照其 7/3/3 与按受试者 96/32/32 划分）；② 归一化肢体长度；③ 显式注入体格测量特征做对抗 |
| **F7** | **解剖 region 与真实运动链错位** | 肘部 token 实际编码了前臂内容 | 关键点锚点集合定义错误 | 用**消融**验证：把 elbow 的 token 置零，看肘角 MAE 是否显著上升 |

### 4.1 F5 的量化论证（可直接写进 paper）

已知 KIST 团队的窗口选择：

| 工作 | 窗口 | 任务 |
|---|---|---|
| Jamsrandorj 2022 EMBC | **9 帧** | 膝/肘角度 |
| Kumar 2022 EMBC | **27 帧** | 下肢角速度 |
| Jamsrandorj 2023 EMBC | **27 帧** | 步态时空参数 |
| Chao 2026 Measurement | `[未验证]` | 髋/膝/踝角度 |

> **我方主张长序列（T=81）的论证方式**：这三个窗口都是**短窗**，且都用于**周期性下肢步态**。
> 而上肢代偿是**非周期、事件驱动**的——代偿往往由**一次失败的动作尝试**触发，
> 其因果链条可能跨越数秒。**因此我需要显式给出"长上下文带来增益"的实验证据**
> （T ∈ {27, 45, 81, 121} 的消融曲线），否则长序列只是成本而非收益。

## 5. 与下游组件的接口契约

```python
# 契约（不得被下游打破）
V_t = tokenizer(I_{t-1:t})          # V_t:  (B, R, d)     R=8, d=256
V   = stack([V_1, ..., V_T])        # V:    (B, T, R, d)  T=81
# 下游 Spatio-Temporal Encoder 期望：(B, T, R, d) 且 R 的顺序固定为 [r0..r7]
```

| 契约项 | 值 | 违反后果 |
|---|---|---|
| region 顺序 | **固定 `[r0..r7]`**（禁止乱序） | `03` 的 region positional encoding 失效 |
| $d$ | **必须等于 VQ 码本维度** | `04` 的 VQ 码本无法对齐 |
| 是否含 padding mask | **必须输出 mask** | 变长序列批处理出错 |

## 7. 风险登记

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| **R1** | **S3（无先验）与 S1/S2 表现相当** | "anatomy-aware"命名被质疑为无用归纳偏置 → **动摇核心创新点 2** | 提前准备：若 R1 成立，需论证**物理合法性指标**（ROM violation / FK consistency）上的增益，而非仅精度增益 |
| **R2** | 关键点检测器成为**性能上限** | 我方精度被外部模型封顶 | **F4** 的 fallback；并在 paper 中明确"不依赖外部姿态机"是设计目标（KIST 的 2023 工作也强调 "does not need a human pose estimator"） |
| **R3** | 上肢数据难以获取大规模标注 | 训练不充分 | 先用 CMU Mocap / Human3.9M 做可行性；再谈自采 |
| **R4** | 审稿人指出「anatomy 先验注入」非首创（Wei 2026 已做肌肉版） | novelty 被削弱 | **主动承认**并给出结构化差异（肌肉 vs 关节链；卷积感受野 vs token 符号）；把 novelty 锚定在**"显式符号化"**上 |
