## 摘要

在非结构化人类环境中运行的机器人不可避免地会遭遇故障，在机器人护理场景中尤为如此。尽管人类通常能够协助机器人恢复，但过多或针对性较差的询问会给人类搭档带来不必要的认知和身体负荷。我们提出了一种面向模块化机器人策略的人机在环（human-in-the-loop）故障恢复框架，其中策略由感知、规划和控制等不同模块组成，任何模块都可能发生故障且通常需要不同形式的人类反馈。我们的框架将校准后的模块级不确定性估计与人类干预成本模型相结合，以决定查询哪个模块以及何时向人类求助。该框架将这两个决策解耦：模块选择器识别出最可能导致故障的模块，而查询算法则决定是请求人类输入还是自主行动。我们在受控的合成实验中评估了几种模块选择策略和查询算法，揭示了恢复效率、对系统及用户变量的鲁棒性以及用户工作负荷之间的权衡。最后，我们将该框架部署在机器人辅助进食获取（bite acquisition）系统上，并在针对具有模拟和真实行动不便受试者的研究中证明，该框架在减少用户负荷的同时提高了恢复成功率。我们的研究结果突显了显式地对机器人不确定性和人类付出进行联合推理，如何能够赋能协作机器人实现更高效且以用户为中心的故障恢复。补充材料和视频可访问：emprise.cs.cornell.edu/modularhil。

## 1 引言

部署在真实环境中的机器人不可避免地会出现失败，尤其是在非结构化家庭环境中协助行动不便的人群进行日常生活活动（activities of daily living, ADLs）时 [13, 37, 40]。尽管人类可以帮助机器人恢复 [3, 10]，但过度的询问会给人类协作者带来认知和身体负担 [16, 36]。因此，设计知道在何时以及向人类询问什么的机器人，对于有效的人机交互至关重要。我们专注于模块化机器人系统，与端到端视觉–语言–动作（vision–language–action, VLA）策略相比，模块化系统具有更高的可解释性，因而更有利于结构化的故障恢复。然而，感知、规划或控制模块中的任何一个都可能出现故障，且每个模块都需要不同形式的人类反馈。

模块化系统中的故障恢复存在两大难点。首先，识别发生故障的模块并非易事；感知错误可能会级联传导至规划与执行阶段，导致难以确定在何处进行干预最为有效。其次，模块的置信度评分往往未良好校准，无法可靠地预测任务是否会成功。过度向用户发起询问可能会令用户感到沮丧，而询问不足又可能导致重复出现故障，从而同时损害任务性能与人机信任。妥善平衡任务成功率与人类工作负荷<sup>1</sup>是协同自主的核心所在。通过将置信度感知推理与人类工作负荷模型 [3, 11, 32] 相结合，我们可以设计出兼顾工作负荷的交互策略，在保持较高用户满意度的同时，更高效地实现故障恢复。这在诸如实体机器人护理等辅助场景中至关重要，在这些场景下，可靠的任务性能和良好的用户体验直接影响着用户对机器人辅助的接受度。

为了解决平衡恢复效率与用户满意度之间的挑战，我们提出了一种用于模块化机器人策略的人在回路（human-in-the-loop）故障恢复框架，该框架将经过校准的模块级不确定性与人类工作量模型相结合。该框架在每次恢复尝试时做出两项关键决策。首先，模块选择器决定查询模块化策略中的哪个组件，例如感知或规划。其次，查询算法决定是向人类发起查询还是完全自主执行动作。这一决策对于权衡任务级成功的预期收益与用户工作量至关重要。我们在序贯决策框架内对这些决策进行了形式化表述，并评估了多种模块选择策略和查询算法。随后，我们将该框架部署在一个机器人辅助进食抓取系统 [3, 13, 14, 37] 上，在包含模拟和真实行动受限者的各项研究中，展示了其在提高恢复成功率的同时降低了用户查询工作量。我们的工作做出了以下创新贡献：

• 我们提出了一种用于故障恢复的模块化人在回路框架，该框架做出两项互补的决策：模块选择器选择要查询的策略组件，而查询算法决定是请求人类输入还是自主执行动作。

• 我们将校准后的模块级不确定性估计与人类工作量模型相结合，以指导这两项决策。

• 我们在受控的合成实验中系统地评估了几种模块选择器（例如直接优化和基于图的方法）以及查询算法（例如查询至置信和感知工作量的变体），揭示了系统与用户变量鲁棒性、效率以及用户工作量之间的权衡。

• 我们在真实的机器人辅助进食（bite acquisition）任务中展示了该方法，在两项模拟行动受限的实验室研究和一项涉及真实行动受限用户的居家研究中，与基线相比，实现了更高的恢复成功率和更低的用户查询工作量。

## 2 相关工作

机器人领域的异常检测与恢复。机器人策略在执行过程中容易发生故障，尤其是在非结构化环境中或遇到新物体时。尽管端到端机器人学习（end-to-end robot learning）最近取得了诸多进展，但这些方法往往难以解释 [1, 8, 41]。相比之下，模块化方法在某些场景下能够提供更具可预测性和可控性的性能。我们的工作侧重于全栈模块化方法，该方法兼顾了机器人系统不同模块之间的故障检测与恢复。虽然一些人在回路（human-in-the-loop）方法 [2, 10, 22] 假设系统已处于需要恢复的故障状态，但我们的方法包含了利用置信度估计进行的故障检测。

正如先前用于机器人故障检测与恢复的在线方法 [2, 7, 29] 一样，使用图表示（graph representation）来表征此类问题是很自然的。整个交互过程也可以通过特定类型的图来建模，涵盖有限状态机（finite-state machines）[7]、MDP/POMDP [12, 29] 以及行为树（Behavior Trees）[2, 6, 26]。尽管图表示在以往的研究中已得到广泛探讨，但我们的方法更进一步，不仅使用图对系统进行建模，还利用图算法来选择查询哪些模块以进行干预。在我们提出的四种用于选择查询模块的方法（我们称之为模块选择器，module selectors）中，有两种是基于图的方法。

寻求帮助的机器人。机器人系统可以根据几种不同的准则来决定向人类发起查询。一些方法在机器人动作执行后检测到故障时寻求帮助 [21, 38]，一些方法基于对机器人潜在采取动作的置信度估计 [27, 33]，还有一些方法基于对征求人类反馈可能产生的信息增益的估计 [10, 30]。与现有工作不同，我们的查询规则同时取决于模块置信度值以及估计的查询时人类工作负载成本。

机器人可以请求的反馈类型也各不相同，涵盖自然语言 [5, 33, 35]、动作 [21, 38, 39] 以及标签 [5]。我们的模块选择方法与具体的反馈类型无关。与以往针对单个动作选择模块 [19, 33] 或奖励模型 [10] 发起查询的工作不同，我们考虑在全栈策略架构中对多个模块进行查询。

一个模块是一个元组 $M = ( \pi , X , y , c , q ( t ) )$，其中 $\pi \cdot : \chi \to y$ 是从输入空间 $X$ 到输出空间 $y$ 的策略函数，$c : X \to$ [0, 1] 是置信度得分，$q(t)$ 是就该模块向人类查询的时间相关成本。例如，模块可以是一个感知模块，从 RGB-D 输入中提取关于机器人环境的几何信息；也可以是一个规划模块，在给定环境中障碍物状态的情况下提取机器人轨迹。我们假设 $G _ { M }$ 中的一个模块（我们记为 $M _ { 1 } )$）接收状态 $s \in S$（即 $\chi = S )$），并且一个模块（我们记为 $M _ { N } )$）产生最终动作 $a \in A \left( { \mathrm { i . e . } } y = A \right)$，其他模块则具有任意的输入/输出空间。

**研究问题**。我们的目标是决定查询**什么**以及**何时**查询，我们将其分解为：(1) 选择单个模块的模块选择器算法 $\psi _ { m s }$，以及 (2) 决定是进行查询还是执行自主动作 $a = \mathcal { S } ( s ) \in \mathcal { A }$ 的查询算法 $\psi _ { q }$。对于特定状态 $s \in S$，模块选择器算法 $\psi _ { m s }$ 和查询算法 $\psi _ { q }$ 应该在交互时域 $T$ 内最小化 $J ( \psi _ { m s } , \psi _ { q })$，即查询成本 $J _ { \mathrm { q u e r y } } ( t ; \psi _ { m s } , \psi _ { q } )$ 与任务成本 $J _ { \mathrm { t a s k } } ( t ; \psi _ { m s } , \psi _ { q } )$ 的加权和：

$$
\begin{array}{l} J (\psi_ {m s}, \psi_ {q}) = \frac {1}{T} \sum_ {t = 1} ^ {T} \left(w J _ {\text {query}} + (1 - w) J _ {\text {task}}\right) \\ = \frac {1}{T} \sum_ {t = 1} ^ {T} \left(w \sum_ {M _ {i} \in \Omega (t)} q _ {i} (t) + (1 - w) (1 - r (t))\right) \end{array}\tag{1}
$$

其中 $w \in [ 0 , 1]$ 决定了最小化人类工作量与高效从故障中恢复之间的权衡，$\Omega(t)$ 表示在时间 $t$ 进行查询的模块集合，$M _ { i }$ 指该集合中的单个模块，$q _ { i } ( t )$ 是模块 $i$ 的查询成本，$r(t)$ 是二值任务奖励，若执行成功则等于 1，否则为 0。

人类反馈。我们假设对于每个模块 $M _ { i ; }$，用户可以通过选择该模块的一个可能输出来提供反馈 $f \in Y_i$（例如，对物体进行分类或选择高层技能）。当我们接收到该反馈时，我们将模块输出替换为专家反馈 $f ,$，并赋予专家置信度 $c = c _ { \mathrm { e x p e r t } } .$。

模块冗余性。整体任务奖励取决于各个模块的成功情况。根据机器人系统架构，模块可以通过两种方式组织：

• 冗余方式：至少有一个模块 $M _ { i }$ 必须成功，它们的组合才能成功，因此成功是一个并集。例如，策略架构可能包含两个预测物体材质属性的冗余模块：一个现成的基础模型和一个特定领域的神经网络 [40]。

• 非冗余方式：所有模块 $M _ { i }$ 都必须成功，它们的组合才能成功，因此成功是一个交集。例如，目标达成操作策略架构可能需要两个模块都成功：一个目标推断模块，以及一个推断通往目标轨迹的规划模块 [25]。

总体成功率 $r ( t )$ 取决于基于机器人系统架构的模块冗余和非冗余组合。

## 4 模块选择器

模块选择器算法 $\psi _ { m s }$ 通过考虑总体目标（公式 1）的单时间步版本来选择要查询的模块。虽然我们无法先验地确定每个模块 $M_i$ 是处于失败还是成功状态，但我们可以获取置信度 $c _ { i }$。我们考虑最小化以下三个代理目标：

代理目标 1（置信度积）：

$$
w \sum_ {M _ {i} \in \Omega (t)} q _ {i} (t) + (1 - w) (1 - \prod_ {M _ {i} \notin \Omega (t)} c _ {i})\tag{2}
$$

代理目标 2（不确定性求和）：

$$
w \sum_ {M _ {i} \in \Omega (t)} q _ {i} (t) + (1 - w) \sum_ {M _ {i} \notin \Omega (t)} (1 - c _ {i})\tag{3}
$$

代理目标 3（依赖冗余）：

$$
w \sum_ {M _ {i} \in \Omega (t)} q _ {i} (t) + (1 - w) (1 - \hat {r} (\Omega (t))\tag{4}
$$

其中奖励估计值 $\hat { r } ( \Omega ( t ) )$ 结合了模块 $M _ { i } \notin \Omega(t)$ 置信度的求和（冗余）与乘积（非冗余）（关于各代理目标如何近似 ${ J } _ { \mathrm { t a s k } }$ 的合理解释见附录 A）。

我们考虑了四种模块选择器算法——两种直接代理优化算法（混合整数规划与蛮力搜索）以及两种基于图的算法（二叉树查询与图查询）。我们还考虑了三种基线模块选择器，其中两种不考虑查询成本或置信度分数，一种仅考虑置信度分数。这些基线包括：(1) 从不查询（Never Query），即不选择任何模块进行查询；(2) 拓扑查询（Topo Query），即简单地选择模块图 $G _ { M }$ 的拓扑排序中第一个先前未被选择的模块；以及 (3) 置信度查询（Confidence Query），即选择置信度分数最低的模块。

## 4.1 代理目标优化

我们考虑了两种直接使用依赖冗余的代理目标（公式 4）的模块选择器。混合整数规划（Mixed-Integer Programming, MIP）模块选择器使用混合整数求解器（SCIP [4]）直接最小化该目标。蛮力（Brute-Force）模块选择器对模块图 $G _ { M }$ 中查询各个模块 $M _ { i }$ 时的该目标值进行评估，然后选择使目标达到最小的模块 $M _ { i }$。

## 5 查询算法

查询算法决定是发起查询，还是执行由最终动作模块 $M _ { N }$ 生成的动作 $\hat{a}$（第 3 节）。我们考虑了四种查询算法和一种基线方法，如图 3（右）所示。它们使用以下原语：

• ForwardPass：表示将当前状态 $s \in \mathsf { \Gamma } S$ 和查询集合 $\Omega ( t )$ 传入模块图 $G _ { M }$ 中的所有模块，以产生最终动作 $\hat{a}$ 和更新后的置信度。在操作任务设置中，这可以表示将当前感知状态（例如 RGB-D 相机数据）传入策略架构，生成期望的末端执行器位姿，以及策略架构中所有模块的置信度。

• Execute：表示执行动作 $\hat{a}$ 并观察整体的布尔型成功结果。在操作任务设置中，这可以表示向机器人发送指令使其移动到期望的末端执行器位姿，并评估操作任务是否成功。

所有查询算法都调用模块选择器 $\psi _ { m s }$ 来选择一个候选模块进行查询，但在执行前进行的查询次数上有所不同。Execute-First 算法最初执行来自 ForwardPass 原语的自主动作 $a$。如果 $a$ 失败，它将在调用模块选择器 $\psi _ { m s }$ 与执行之间交替进行，直到成功。Query-then-Execute 始终在调用模块选择器 $\psi _ { m s }$ 与执行之间交替进行，直到成功。

## 6 合成仿真：系统性消融实验

我们开发了一个合成模块仿真，以研究系统变量和用户变量如何影响模块选择器和查询算法的性能（第 4、5 节）。我们的仿真使用通过随机模块图 $G _ { M } ,$ 连接的 $M$ 个模块，其中模块被实现为对布尔输入（包括布尔状态 $S$）进行操作的逻辑门（AND/OR）。单个模块被设置为处于成功或失败状态：处于成功状态的模块输出其逻辑门的值，而处于失败状态的模块始终输出 False。有关超参数的详细信息（包括代理目标权重和 GraphQuery $K$），请参见附录 F.1（App. F.1）。

自变量。我们考察了涵盖影响机器人以及人机交互性能的关键系统和用户因素的四个变量（完整设置见附录 F.1）。我们考虑了三个系统变量：

• 模块数量 $M$（第 6.1 节）。机器人策略架构中的模块数量可能有所不同，从简单的模块化感知、规划和控制架构，到涉及多达 100 个模块的更复杂模块化架构。

• 模块冗余/图结构 $G _ { M }$（第 6.2 节）。机器人策略架构包含冗余和非冗余结构（第 3 节）。不同的模块选择器基于其代理目标具有不同的冗余假设。我们考虑了 4 种具有不同模块类型和排序的冗余结构：全冗余（全或/all-OR）、全依赖（全与/all-AND）、先全冗余后全依赖（先或后与/OR-then-AND）、先全依赖后全冗余（先与后或/AND-then-OR）。

• 置信度值 $c _ { i } \ ( { \bf S e c . } \ 6 . 3 )$。机器人策略架构中各个模块的置信度分数可能各不相同。我们为 $G _ { M }$ 中的每个模块分配高置信度值或低置信度值。此外，我们将模块的置信度值视为该模块处于成功状态的概率。

我们还考虑了一个用户变量：

• 查询成本 $q_i$（第 6.4 节）。由于反馈类型的多样性，策略架构中每个模块的查询成本可能有所不同。我们考虑了所有模块统一查询成本 $q _ { i }$ 的不同取值。

我们分别单独改变各个自变量。当某个变量未被改变时，我们将其值固定如下：(1) =10 个模块，(2) 完全依赖（全与 / all-AND）模块结构，(3) 3 个模块的置信度为 0.1，其余所有模块的置信度为 1，(4) 均匀查询成本为 0.32。我们还假设专家无噪声 $( c _ { \mathrm { e x p e r t } } { = } 1 . 0 )$。此外，在分析模块选择器时，我们使用固定的查询算法（Query-Until-Confident-Workload-Aware）；而在分析查询算法时，使用固定的模块选择器（GraphQuery）。

评价指标。我们使用 5 项指标评估这些方法（越低越好）：

• 任务成本（Task Cost）。如果智能体在  个时间步后成功从故障中恢复则为 0，否则为 1。这表示机器人在其时间跨度约束下是否能够从故障中恢复。

• 查询成本（Query Cost）。$\textstyle \sum _ { t = 1 } ^ { T } b _ { t } q _ { i } ( t )$，其中  是实现成功所需的时间步数或最大时间跨度（与模块数量 $N )$ 成正比），$b _ { t }$ 是表示机器人在时间步  是否进行了查询的二元指示变量。这代表用于从机器人故障中恢复所消耗的用户总工作量。

• 失败尝试次数（Number of Failed Attempts）。$\textstyle \sum _ { t = 1 } ^ { T } g _ { t }$，其中 $g _ { t }$ 是一个二元指示变量，表示在时间步 $t$ 是否发生了执行失败。这代表机器人在从故障中恢复之前所经历的失败机器人执行次数。

• 计算时间（Computation Time）。$\textstyle \sum _ { t = 1 } ^ { T } ( T i m e ( t ) )$，其中 $Time(t)$ 是连续 EXECUTE 语句之间的总运行时间。这代表机器人在每个时间步运行模块选择器和查询算法所消耗的总计算时间（不包括查询所需的时间）。

• 总时间步 $T$（Total Timesteps $T$）。这包括机器人在从故障中恢复之前所经历的查询次数和执行失败的次数。

Fig. 4(a) 比较了每个变量下的算法性能，重点展示了一项指标$^{2}$（完整结果详见 App. F）。我们还在 App. F.6 中重点展示了改变另一个用户变量——专家置信度水平 $c _ { \mathrm { e x p e r t } } \left( \mathrm { S e c . } \ 3 \right)$ 的结果，我们发现 BruteForce 和 GraphQuery 模块选择器以及两种 Query-Until-Confident 查询算法在高专家置信度区间表现最佳，且性能随着置信度的降低而下降。

## 6.1 改变模块数量 $M$

模块选择器（Module selectors）。对于除 NeverQuery 和 TopoQuery 之外的所有方法，除计算时间（Computation Time）外的所有指标对 $M$ 均是不变的。ConfidenceQuery 是最具可扩展性的方法，其在 $M$ 上的时间复杂度呈线性关系（图 4(a)），这使其在大型策略架构中计算效率最高。由于计算时间随 $M$ 扩展，需要大量时间步的方法（NeverQuery 和 TopoQuery）会产生更高的计算时间。

查询算法（Querying algorithms）。对于除 Query-For-All 之外的所有方法，除计算时间外的所有指标对 $M$ 均是不变的，后者的任务成本（Task Cost）和查询成本（Query Cost）分别为 0 和 0.96。我们注意到 Query-Until-Confident-Workload-Aware 的计算时间最高（图 4(a)），这是因为其包含了预测查询成本的额外步骤，而其他三种方法的计算时间数值几乎相同。对于大型机器人策略架构，如果运行时间至关重要，我们建议不要选择 Query-Until-Confident-Workload-Aware。

## 6.2 改变图结构 $G _ { M }$

模块选择器。在所有方法中，全 OR（all-OR）结构下的所有指标均较低（查询成本除外，它对图结构是不变的）。对于这种冗余结构，请求帮助以从故障中恢复所带来的收益很小，从而使 NeverQuery 和 TopoQuery 在总失败尝试次数（Total Failed Attempts）和总时间步数（Total Timesteps）上表现良好。对于其他冗余结构，方法间的排名（图 4(a)）保持不变。GraphQuery 与其他方法相比具有竞争力，即使在其代理目标与冗余结构不匹配时也是如此。

查询算法。在所有方法中，全 OR 结构下的所有指标均较低。通常情况下，两种 Query-until-Confident 变体的总失败尝试次数都是最低的，但在全 OR 设置下除外（此时 Execute-First 和 Query-then-Execute 的表现优于它们）。因此，如果机器人策略架构不是完全冗余的，我们推荐使用任一 Query-until-Confident 变体，以实现恢复效率的最大化。

## 6.3 改变置信度值 $c _ { i }$

模块选择器。当置信度重叠时，各方法的所有指标（例如任务成本，图 4(a)）均更高。由于无论置信度水平如何，BruteForce、GraphQuery 和 ConfidenceQuery 都是最具竞争力的几种方法，因此我们推荐其中的任一方法。

查询算法。当置信度重叠时，除 Query-Until-Confident 和 Query-For-All 之外，各方法的所有指标（例如任务成本，图 4(a)）均更高。我们发现 Query-Until-Confident 方法对置信度变化最为鲁棒。如果置信度得分在机器人策略架构中区分良好，我们推荐使用任意方法；如果置信度值存在重叠，则推荐使用 Query-Until-Confident。

## 6.4 改变查询成本 

模块选择器。除任务成本外，所有指标对 <sub></sub> 均保持不变，与其他模块选择器相比，BruteForce、GraphQuery 和 ConfidenceQuery 具有更低的总时间步数（图 4(a)）。无论用户查询工作量的大小如何，我们都推荐使用这些模块选择器中的任意一种。

查询算法。除查询成本外，在各查询算法中，所有指标在很大程度上对 $q _ { i }$ 保持不变。由于两种 Query-Until-Confident 变体均具有最低的总失败尝试次数，且总时间步数通常更低（图 4(a)），我们推荐使用这些变体中的任意一种。

## 7 合成仿真：模块异质性

我们现在考虑一个包含额外用户变量（查询成本方差 $\beta$）的仿真设置，允许查询成本 $q _ { i }$ 在不同模块之间变化。这为不同反馈类型之间更真实的成本变化进行了建模。我们在标称值 $Q$ 周围均匀采样每个 $q _ { i }$，即 $q _ { i } { \sim } \mathrm { U n i f o r m } [ ( 1 { - } \beta ) Q , ( 1 { + } \beta ) Q ]$，其中 $Q=0.32$（即第 6 节中未变化时使用的查询成本值）。我们基于任务成本（Task Cost）比较了第 6 节中表现最佳的模块选择器：感知查询成本的方法 GraphQuery，以及仅基于置信度的基线方法 ConfidenceQuery（两者均采用 Query-Until-Confident-Workload-Aware）。

我们发现，在总时间步（Total Timesteps）和任务成本（Task Cost）指标上，GraphQuery 均一致优于 ConfidenceQuery，尤其是在模块置信度重叠或工作负载方差较高时（见图 4(b) 中的 Task Cost）。在这些条件下，置信度较低且工作负载较高的上游模块可能会成功，而置信度较高但工作负载较低的下游模块可能会失败。ConfidenceQuery 会错误地优先选择这些上游模块，而 GraphQuery 则能正确选择下游模块（完整结果见附录 G）。

## 9 讨论

我们的框架很容易扩展到其他模块化机器人系统，我们通过考虑两个额外的领域来说明这一点：具有视触觉感知冗余的辅助进食架构 [40]，以及大型多机器人集群系统 [34]。进食系统自然地映射为“先或后与”（OR-then-AND）冗余结构（归因于感知冗余），且查询成本较低（ = 0.16），从而得出与我们主要设置相同的推荐方案（Fig. 4）。我们可以通过设置  = 100 对集群领域进行建模以反映其规模，并采用“全或”（all-OR）冗余结构，这使得具有优异可扩展性的 ConfidenceQuery 模块选择器成为首选（Fig. 4，第一列），同时可搭配任一 Query-until-Confident 查询算法变体。这两个推荐结果均与领域直觉相符。

将我们的框架应用于食物咬取（bite acquisition）的一个关键挑战是校准模块置信度得分。这包括对 RT-1 进行改造以生成新的置信度得分，并为所有模块开发一套通用的校准流程，使其能够在各自不同的经验置信度分布下运行（附录 C.1-C.2）。尽管我们的置信度估计已经得到了合理的校准，但未来的工作可以探索保形预测（conformal prediction）[27, 33] 或数据驱动的校准方法 [20]。未来的工作还可以考虑适用于更复杂冗余结构的模块选择器。虽然我们研究了针对置信度乘积和不确定性求和目标的基于图的模块选择器，但混合选择器可以根据哪些模块存在冗余来自适应地结合这些结构。最后，除了我们观察到的满意度趋势之外，更长期的用户研究可能会进一步区分不同的人在回路（human-in-the-loop）算法。未来的评估还可以考虑更多样化的真实场景菜肴，涵盖更丰富的食物种类、更复杂的几何结构以及预操作技能（pre-manipulation skills）[15, 18, 40]。

## A 代理目标

代理目标 1 的合理性说明：第二项可以作为 $1 - \mathbb { E } \big [ r _ { \mathrm { t a s k } } \big ]$ 的合理近似，其中期望是对模型不确定性（由 $\displaystyle c _ { i }$ 表示）所取的：

$$
\begin{array}{l} \mathbb {E} [ r _ {\text {task}} ] = P (\cap_ {i} M _ {i} \text {succeeds}) \\ \qquad = \prod_ {M _ {i}} P (M _ {i} \text {correct|predecessor} M _ {j} \text {correct}) \\ \qquad = \prod_ {M _ {i} \notin M _ {q}} c _ {i} \end{array}
$$

代理目标 2 的理论依据：设 $\begin{array} { r } { { u } _ { i } \ = \ 1 - \ c _ { i } } \end{array}$ 为模块 $i$ 的不确定度。那么我们可以利用联合界（union bound）证明：

$$
\begin{array}{l} P (\text {system fail}) = P (\cup_ {i} M _ {i} \text {fails}) \\ \leq \sum_ {i} P (M _ {i} \text {fails}) \\ = \sum_ {M _ {i} \notin M _ {q}} u _ {i} + \sum_ {M _ {i} \in M _ {q}} 0 \\ = \sum_ {M _ {i} \notin M _ {q}} u _ {i} \end{array}
$$

因此，代理目标 2 中的任务分量是 $P(\text{system fail}) = 1 - \mathbb { E } [ r _ { \mathrm { t a s k } } ]$ 的一个上界，这意味着代理目标 2 是原始目标的一个松弛上界，因而最小化代理目标 2 也能够最小化原始目标。

## B 算法性能分析

假设我们有一个模块图 $G _ { M }$，其中恰好有一个处于失败状态的模块（记作 $M _ { f }$），而所有其他模块均处于成功状态。此外，我们假设所有模块的查询成本均为 $q _ { i } = 0.1$。失败模块的置信度为 $c _ { f } = 0.1$，而所有其他模块的置信度均为 $c _ { i } = 0.1$。

## B.1 GraphQuery

回想在 GraphQuery 中，我们为自主边（autonomous edges）赋予边成本 $C ( e ) \ = \ 1 - c _ { i }$。因此，若 $1 - c _ { i } > \epsilon q$，图算法就会对模块发起查询；即：

$$
q <   (1 - c _ {i}) / \epsilon\tag{5}
$$

## C 咬取架构

图 2（左）展示了我们在工作中使用的模块化咬取（bite acquisition）架构，该架构改编自最先进的架构 [18]，并包含了新颖的基础模型组件。

该自主系统由四个子模块组成，每个子模块都具有相关的置信度估计：

$\mathbf { M } _ { 1 } \colon \mathrm { G P T } \ – 4 0 \ \left[ 1 7 \right]$ 食物类型检测器，处理整盘 RGB 图像 <sub>RGB</sub> ∈ $\scriptstyle : \mathbb { R } ^ { H \times W \times 3 }$ 并识别一组候选食物标签 $\mathcal { L } = \{ l _ { 1 } , l _ { 2 } , \ldots , l _ { K } \}$，其中 $K$ 是检测到的独特食物类别数量（例如，圣女果、菠萝等）。从该集合中，$M_1$ 选择具有最高置信度得分的单个标签作为其输出：

$$
M _ {1} (z _ {\mathrm{RGB}}) \rightarrow l ^ {*}
$$

$\mathbf { M } _ { 2 } { \mathrm { : } }$ GroundingDINO [23] 边界框检测器，以来自 $M _ { 1 }$ 的所选食物类型标签 $l^*$ 以及餐盘 RGB 图像 $z_{\mathrm{RGB}}$ 作为输入。它输出一个或多个边界框 $\mathcal { B } ( l ^ { * } ) = \{ b _ { 1 } , b _ { 2 } , . . . , b _ { J } \}$，其中每个 $b _ { j }$ 对应于图像中检测到的食物类型 $l^*$ 的一个实例。因此，

$$
M _ {2} (z _ {\mathrm{RGB}}, l ^ {*}) \to \mathcal {B} (l ^ {*}).
$$

$\mathbf { M } _ { 3 } \colon \mathrm { G P T } \mathbf { - } 4 0 \ \left[ 1 7 \right]$ 技能选择器，在给定检测到的食物标签 $l^*$ 及其对应边界框 $b _ { i }$ 的情况下，预测最优技能 $a _ { i } ^ { h } \in \mathcal { A } _ { h }$，其中 $\mathcal { A } _ { h }$ 是一组技能（例如：串刺（Skewering）、舀取（Scooping）、卷取（Twirling））。

$$
M _ {3} (l ^ {*}, b _ {i}) \rightarrow a _ {i} ^ {h}
$$

$\mathbf { M } _ { 4 } \colon$ 一个 VLA 模型 RT-1，用于将技能动作 $a _ { i } ^ { h }$ 细化为精确的技能参数 $a _ { i } ^ { l } \in \mathbb { R } ^ { 4 }$。它输入技能动作 $a _ { i } ^ { h }$ 以及来自相应边界框 $b _ { i }$ 的裁剪图像。我们通过在包含 SPANet 样本 [9] 以及我们收集的约 1,000 张额外标注图像的聚合数据集上，使用新的回归投影头对其进行微调，从而使 RT-1 适用于模块化控制。这种设计使我们能够将 RT-1 的不确定性完全归因于其技能参数预测，而 $M _ { 1 } , M _ { 2 }$ 和 $M _ { 3 }$ 则分别处理食物分类、位置估计和技能选择。

特定技能参数化。我们使用统一的 2D 动作向量 $a _ { i } ^ { l } = ( x _ { 1 } , y _ { 1 } , x _ { 2 } , y _ { 2 } )$ 来表示所有低层技能，其语义基于所选技能 $a _ { i } ^ { h }$。对于叉取（skewering）和卷取（twirling），交互点定义为两个预测点之间的中点：

$$

$$

叉齿方向 $\theta$ 计算如下：

$$
\theta = \arctan (y _ {2} - y _ {1}, x _ {2} - x _ {1}).
$$

对于舀取（scooping）动作，$( x _ { 1 } , y _ { 1 } )$ 表示舀取动作的起点，$\left( { x _ { 2 } , y _ { 2 } } \right)$ 表示舀取轨迹的终点。这种参数化方式遵循了以往关于以视觉为条件的操作原语的研究（例如 FLAIR [18]），同时在不同异质技能之间实现了统一的连续动作空间。

$$
M _ {4} (a _ {i} ^ {h}, b _ {i}) \rightarrow a _ {i} ^ {l}

## C.1 校准数据集与置信区间

为了支持我们食物获取（bite-acquisition）流水线中具有不确定性感知的决策，我们参考了 [28] 中提及的方法。我们为所有模块构建了校准数据集及相关的置信区间：$M _ { 1 } , M _ { 2 } , M _ { 3 } , M _ { 4 }$。每个校准数据集都记录了每个实例的模型输出、其置信度得分以及对应的真实标签（ground-truth labels）。

$M_1$ 的校准。我们使用了来自 [18] 的菜肴以及所有可用的餐盘图像。对于图像中的每种食物类型，$M _ { 1 }$ 会生成带有对数概率的候选标记（标签）排序列表。这些对数概率经过指数运算、换算为百分比并保留两位小数以得出置信度得分，最高排名的标记（置信度得分最高的标记）被选为该食物类型的预测标签。

• 如果排名前一（top）的标记（token）与该食物类型的真实标签（ground-truth label）相匹配，我们就会向 $M _ { 1 } ^ { \prime } s$ 的校准数据集中添加一条包含前五（top-5）标记、它们的置信度分数以及真实标签的条目。

• 如果真实标签不在预测结果中，我们则进行标签替换：优先使用未匹配的食物类型预测（如果存在），或者作为兜底方案，使用同一图像中已匹配的预测。被替换的标记及其相关分数将与真实标签一同存储。

该替换过程确保了每种目标食物类型都能为校准数据集贡献一个条目，这对于计算合理的参考区间是必不可少的。由此为 $M _ { 1 }$ 生成了一个包含 96 个样本的基于置信度的校准数据集。

$M _ { 2 }$ 的校准。对于 $M _ { 1 }$ 中使用的同一组图像，我们遍历由 $M _ { 2 }$ 生成的所有边界框（bounding boxes）。每个边界框都经过人工评估，以确定其是成功的（准确捕获目标食物类型）还是不成功的（$ \mathrm { e . g . } $ 包含错误的食物类型、空白区域或背景噪声）。对于每个边界框，我们记录 GroundingDINO 输出的置信度得分。如果边界框被判定为成功，其置信度得分将被添加到成功列表中；如果不成功，其置信度得分将被添加到失败列表中。在此设置中，成功得分起到“首选”（top-choice）置信度值的作用，而失败得分则对应于 $M _ { 1 }$ 和 $M _ { 3 }$ 中使用的“次选”（second-choice）值。这为 $M _ { 2 }$ 生成了一个包含 76 个样本的校准数据集，由成功（61 个样本）和失败（15 个样本）的置信度分布组成，用于构建与其他模块类似的区间。

$M_3$ 的校准。来自 $M_1$ 的已识别（或替换）标签，连同来自 $M_2$ 的该食物类型对应的边界框图像，一起传递给 $M_3$。为确保输入的可靠性，我们将此步骤限制在被视为有效的边界框内——即那些准确捕获了该食物类型、而不仅仅是空白区域等的边界框。该模块输出候选技能标记（token）及其对数概率，并使用与 $M_1$ 相同的步骤将其处理为百分比置信度分数。与 $M_1$ 中的步骤类似，首选标记被作为预测技能。对于每个食物类型和边界框图像对，我们在 $M_3$ 的校准数据集中存储排名前 3 的标记、它们的置信度分数以及真实（ground-truth）技能标签。这为 $M_3$ 产生了一个包含 66 个样本的基于置信度的校准数据集，与 $M_1$ 的数据集类似。

$M_4$ 的校准。由于 RT-1 是确定性的，我们使用蒙特卡洛 Dropout（Monte Carlo Dropout）在其预测中引入随机性。具体而言，我们在推理过程中启用 dropout，并以 16 次前向传播为一个批次运行模型。这会在 $M _ { 4 }$ 输出空间上产生一个分布，并由此计算方差。该方差随后作为我们衡量模型对其预测置信度的指标。我们使用了与 $M _ { 3 }$ 中相同的边界框，但采用了人工标注的技能真值标签。这为 $M _ { 4 }$ 产生了一个包含 66 个样本的基于置信度的校准数据集。

置信区间。从每个校准数据集中，我们计算首选标记（top token）置信度分数的均值 $( \mu ^ { * } )$ 和标准差 $( \sigma ^ { * } )$。我们对次选标记（second top token）进行相同的操作，得到 $\mu ^ { + }$ 和 $\sigma ^ { + }$。利用这些值，我们定义了以下置信区间：

$$
I _ {\mathrm{TopConf}} = \left[ \mu^ {*} - \sigma^ {*}, \mu^ {*} + \sigma^ {*} \right], I _ {\mathrm{SecondTopConf}} = \left[ \mu^ {+} - \sigma^ {+}, \mu^ {+} + \sigma^ {+} \right].
$$

这些区间捕捉了所有校准实例中排名第一和第二的预测的置信度分数的期望分布。

## C.2 校准置信度分数

为了获得所有模块的校准置信度分数，我们应用了一条将原始置信度值映射为稳定的二值（binary value）的规则。对于给定的置信度分数 $c ^ { * }$（对应于某个实例的最佳预测），我们检查 $c ^ { * }$ 是否落在校准的最佳词元（top-token）区间之外，或者落在第二词元（second-token）区间之内：

$$
C o n f _ {c a l} (c ^ {*}) = \left\{ \begin{array}{l l} 0, & \text { if } (c ^ {*} \notin I _ {\text { TopConf }}) \lor (c ^ {*} \in I _ {\text { SecondTopConf }}), \\ 1, & \text { otherwise. } \end{array} \right.
$$

在这里，函数 $f _ { c a l } ( c ^ { * } )$ 生成一个二值的校准置信度分数：当预测被视为低置信度（不确定）时为 0，当预测被视为高置信度（有把握）时为 1。这些校准后的分数随后被流水线中的其他组件使用，以确定是否针对该特定模块向人类进行查询。

将决策建立在从校准数据估计的置信区间上，使系统能够同时识别低置信度的正确预测与过度自信的错误预测，从而产生比仅凭原始概率更稳定的置信度信号。通过引入校准后的置信度分数，我们确保系统基于具有可解释性且具有统计依据的区间进行推理，而非依赖充满噪声的概率值，进而在所有模块中提供更可靠、更一致的置信度估计。

## C.3 用于错误恢复的检索增强反馈（Retrieval-Augmented Feedback for Error Recovery）

为了使系统能够从以往的错误中恢复并随着时间的推移进行自适应，我们将检索增强生成（retrieval-augmented generation, RAG）组件集成到了食物类型识别模块 $( M _ { 1 } )$ 和技能选择模块 $\left( M _ { 3 } \right)$ 中。该组件的目标是将人类提供的反馈纳入持久化存储中，从而使流程在未来遇到相似输入时能够检索并复用纠正信息。这种机制提供了一种从错误中持续学习的途径，并减少了对人类用户的重复询问。

嵌入式反馈存储库（Embedded Feedback Store）。我们实现了一个 EmbeddedFeedbackStore，用于记录反馈条目，这些条目包括餐盘图像（针对 $m_1$）或边界框图像与食物标签（针对 $m _ { 3 } )$，以及由人类提供的修正输出。对于 $m _ { 1 }$，使用 CLIP 视觉编码器 [31] 直接从餐盘图像计算嵌入向量，生成纯视觉表征。对于 $m _ { 3 } ,$，使用 CLIP 视觉-语言模型 [31] 从目标食物条目的边界框图像及其文本标签联合计算嵌入向量，从而捕获用于技能选择的视觉和语义上下文。所有嵌入向量均经过归一化，并与对应的真实修正值一起作为向量持久化存储，在我们的设置中，该修正值对于 $M _ { 1 }$ 而言是指正确的食物类别标签，对于 $M _ { 3 }$ 而言是指正确的技能。因此，每当系统针对特定模块向人类查询反馈时，对应的输入（图像或带有标签的边界框图像）连同其修正后的输出都会被添加到反馈存储库中，以便未来进行检索和复用。

检索。在推理阶段，当 $M _ { 1 }$ 或 $M _ { 3 }$ 产生预测时，反馈存储库会计算当前输入的 CLIP 嵌入，并使用余弦相似度检索最相似的历史条目。如果最佳匹配超过相似度阈值，则重用存储的修正。该修正会被转换为概率分布：检索到的食物类型标签（或技能）被赋予与相似度得分成正比的概率，而剩余的概率质量则均匀分布在其他候选 token 上。如果未找到足够相似的修正，流水线将默认采用该模块的预测。

这种基于 RAG 的机制使流水线能够从错误中进行增量学习。通过利用相似度搜索，系统避免了在相似输入上重复先前的错误，并减少了不必要的人工查询。这提供了一种轻量但有效的持续适应形式。

建议。对于模块选择器，我们建议使用 BruteForce 或 GraphQuery，因为无论置信度水平如何，它们在各项指标上都最具竞争力。对于查询算法，我们建议使用 Query-until-Confident（除非在全 OR 设置下，此时 Execute-First 或 Query-then-Execute 在最小化总时间步长方面表现最佳）。

## F.6 额外消融实验：专家置信度

我们针对一个额外的用户变量进行了消融实验：专家置信度值（$c _ { \mathrm { e x p e r t } }$，在 Sec. 3 中介绍），以了解不完美的人类反馈如何影响模块选择器和查询算法的性能。在我们的仿真中，专家置信度 $c _ { \mathrm { e x p e r t } }$ 表示模块查询为该模块产生正确逻辑值的概率。我们针对 $c _ { \mathrm { e x p e r t } } \colon [ 1 , 0 . 8 , 0 . 6 , 0 . 4 ]$ 考虑了以下设置，范围从完美专家（在 Sec. 6 中考虑）到置信度较低的专家。此外，我们调整了模块选择器，以便为已经被查询过的模块分配 $\mathbf { \sigma } _ { c _ { \mathrm { e x p e r t } } }$ 的置信度。

F.6.1 模块选择器（Module selectors）。我们发现，随着 $c _ { \mathrm { e x p e r t } }$ 的降低，所有模块选择器的性能都会下降（Figure 11），在最低置信度设置 $\left( c _ { \mathrm { { e x p e r t } } } \ = \right.$ 0.4) 下，任务成本（Task Cost）会恶化至 0。当专家置信度足够低时，模块选择器无法确定模块是否收到了正确的反馈，从而导致对同一个（上游）模块进行冗余查询。在各个模块选择器中，我们发现在高专家置信度区间内，Brute Force、GraphQuery 和 ConfidenceQuery 的表现最好。我们还发现，无论专家置信度取值如何，BinaryTreeQuery 往往都存在欠查询（under-query）的倾向，从而导致高昂的任务成本。

F.6.2 查询算法（Querying algorithms）。我们再次发现，随着 $c _ { \mathrm { e x p e r t } }$ 的降低，所有查询算法的性能都会下降（Figure 11）。在较高的专家置信度下，我们发现两种 Query-Until-Confident 变体在总时间步（Total Timesteps）和总失败尝试次数（Total Failed Attempts）方面表现最佳。在较低的专家置信度下，我们注意到 Query-Until-Confident 往往会过度查询（over-query），因为代理任务目标始终无法达到足够高的水平以停止查询；而 Query-Until-Confident-Workload-Aware 则倾向于欠查询，因为查询带来的置信度增益不足以抵消查询成本。

建议（Recommendations）。对于中等到高专家置信度的情况，我们推荐使用 BruteForce、GraphQuery 或 ConfidenceQuery 模块选择器，因为它们能在较短的总时间步下实现最低的任务成本。此外，如果最看重的是最小化总时间步，我们推荐使用两种 Query-Until-Confident 查询算法；在其他场景下，则推荐使用 Execute-First 和 Query-then-Execute 查询算法。

## H.2 客观指标

我们定义以下 3 项客观指标：

(1) 每盘平均查询次数（Mean Queries Per Plate）：$\begin{array} { r } { \frac { 1 } { B } \sum _ { b = 1 } ^ { B } \sum _ { t = 1 } ^ { T _ { b } } } \end{array}$ $\mathbb{I}\{\text{queried at } t\}$，其中 $B$ 为每盘的进食次数（bites），$T _ { b }$ 为进食 $b$ 所需的时间步数。

(2) 每盘平均执行次数（Mean Executions Per Plate）：$\begin{array} { r } { \frac { 1 } { B } \sum _ { b = 1 } ^ { B } \sum _ { t = 1 } ^ { T _ { b } } } \end{array}$ $\mathbb{I}\{\text{executed at } t\}$，其中 $B$ 和 $T _ { b }$ 的定义同上。

(3) 每盘平均成功进食次数（Mean Successful Bites Per Plate）：$\textstyle { \frac { 1 } { B } } \sum _ { b = 1 } ^ { B }$ $\mathbb{I}\{b \text{ succeeded}\}$，其中 $B$ 的定义同上，若机器人在 $T _ { b }$ 个时间步后成功获取该口食物，则定义进食 $b$ 成功。
