# 归档机制

> **成文日期**：2026-10-03 · **触发**：用户要求建立归档文件夹与可复用归档机制
> **性质**：**机制文件**（不是一次性事件记录）。`AGENT.md` §4 的「归档与迁移规则」是**约束**，
> 本文件是**执行流程**，两者必须一起读。
> **归档目录**：[`../11_归档/`](../11_归档/)（顶层编号 `00`–`10` 已占满，`11` 是唯一可用编号）

## 0. 一句话

**归档 = 退役但仍需留证；不是垃圾桶，也不是备份盘。**

## 1. 为什么需要机制（不是规则）

`AGENT.md` §4 早在 2026-09-30 就立了 7 条归档规则，但它们**绑定在一次具体迁移上**（「本次归档范围只包括改版前的三份原件」）。结果是：

- 规则无法被下一次迁移直接复用；
- 实际归档散落三处、形态各异：`04_实验设计/D435i_四问任务包/历史归档`、`01_参考论文/_backup_20260930_2214`、`.pi/goals/archived`（后者由运行时管理，不属本机制）；
- **没有任何一处能回答「某文件为什么不见了、当时叫什么、能不能复活」**。

📌 本项目已经反复为同一类问题付出代价：**K8**（定位卡绕过链路落盘，成为无法复现的孤儿卡）、
**K22**（重建脚本静默删库 4 条，含 ISB Part II）、
**K31**（写回键失配使一条定级结果被静默丢弃）。
**三者都不是「文件不见了」，而是「文件不见了且没人说得清」。** 归档机制要解决的就是这一类。

## 2. 准入：什么可以进归档

同时满足「**被取代或已退役**」与「**仍需留证**」才准入。

| # | 准入类型 | 典型例子 | 必录字段 |
|---|---|---|---|
| A1 | **被证伪的论证原文** | 主张 C 那句可写的英文句被 F29 全文级推翻 | 原文、被谁推翻、推翻依据 |
| A2 | **被取代的现行文档版本** | 某版索引/报告在重建后失效 | SHA-256、取代它的新版本路径 |
| A3 | **迁移的回滚证据** | 移动清单、逐条 diff、删除清单 | 源→目标全表、可逆性 |
| A4 | **外部会话在途快照**（台账 I 类） | 并发进程写入前的目录状态 | 快照时刻、并发进程 |
| A5 | **退出执行但仍需留证的子项目产物** | D435i 四问任务包的旧方案 | 退出原因、现行替代物 |

## 3. 不准入：明确排除（防归档退化成垃圾桶）

| # | 排除类型 | 正确去处 | 理由 |
|---|---|---|---|
| X1 | **重复副本**（同 DOI / 同字节的冗余下载） | **回收站**，不进归档 | 归档是长期留证；可随时再下载的东西不该占归档位。2026-10-03 清理 29 份重复副本，全部走回收站而非归档 |
| X2 | **可由脚本重新生成的中间产物** | 重建，或留在 `/tmp` | `candidates.json` / `resolved.json` 的旧版随时能重跑出来，归档它只是制造第二份真相 |
| X3 | **未通过人工裁定的候选** | 留在候选池，或回收站 | 未裁定 ≠ 已退役；进归档等于给它盖了个「已处理」的假章 |
| X4 | **仍被现行文档引用的文件** | **先解除引用**再归档 | 归档区的东西被活跃文档引用 = 事实仍是活的，位置却已退役 |
| X5 | 临时脚本、`.DS_Store`、空目录、操作系统垃圾 | 回收站 | 不是知识 |

## 4. 归档条目的强制结构

`11_归档/` 下**每个归档单元一个目录**，目录内**必须**有 `ARCHIVED.md`：

```
11_归档/
  README.md                      ← 归档总索引（活文档，随每次归档更新）
  归档机制.md → ../06_附录/归档机制.md   ← 软链接，从归档区直接可达机制
  <YYYY-MM-DD>_<单元名>/
    ARCHIVED.md                  ← 强制清单，见下
    <被归档的文件本体>
```

### 4.1 `ARCHIVED.md` 必录字段

缺任一字段即视为**归档未完成**（等同丢失）：

| 字段 | 说明 |
|---|---|
| **原路径** | 归档前的规范路径，精确到文件名 |
| **归档原因** | 引用准入编号（A1–A5），并写清**被谁/被什么取代** |
| **归档日期** | `YYYY-MM-DD` |
| **SHA-256** | 每个被归档文件的哈希（`AGENT.md` §4.3 已要求「保持字节内容」） |
| **仍被引用？** | 明确「是/否」+ 引用位置清单；**若是，归档无效**，须先解除 |
| **复活条件** | 什么情况下应把它移回活跃区（写可判定的条件，不写「必要时」） |

## 5. 引用纪律（最重要的一条）

1. **归档区内容不得被现行文档当作证据引用。** 它的作用是解释「为什么变了」，不是支撑「现在是什么」。
2. 现行文档若必须提及历史，**同时指向现行口径**（`AGENT.md` §4.6）。
3. 🔴 **台账里的 `[x]` 与归档是两件事**：台账记「这个缺口已闭合」，归档记「闭合过程中被推翻/被取代的东西」。**闭合不等于无需留证。**

## 6. 复活流程

1. 写明复活理由，并对照该条目的「复活条件」；
2. 从 `11_归档/` 移回原路径（`AGENT.md` §4.4：现行文件只有一个规范路径，**移回原位而非另开新位**）；
3. 更新 `11_归档/README.md`：标记为「已复活 + 复活日期 + 复活后的路径」；
4. **更新全部直接引用**（Markdown 链接、导航描述、运行说明、索引计数）；
5. 跑验收（`AGENT.md` §7）。
