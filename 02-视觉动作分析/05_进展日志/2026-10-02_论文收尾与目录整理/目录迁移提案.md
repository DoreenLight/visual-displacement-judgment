# 目录迁移提案（已按确认范围执行）

> 原提案范围与回滚规则保留如下。执行结果见[迁移执行记录](目录迁移执行记录.md)；40 文件已迁移，旧路径均消失，本地验收通过。

## Proposal · 确认范围

仅将下面 **40 个文件**从 `06_附录/Transformer语料工具/` 移到同级的 `06_附录/生物力学语料工具/`；新增后者 `README.md` 作为生物力学流程入口。精确路径、执行前 SHA-256 与逆向清单见[机器清单](目录迁移提案.json)。确认只授权本表，不授权扩大范围。

## Why · 按职责拆分

现有 Transformer 工具目录同时承载 TF 与独立 BM 检索、筛选、取件、入库、索引、展示和证据扫描。两个语料有各自候选、解析结果、报告与构建入口，具备独立变更责任。选择同级职责边界，不创建 `scripts/`、`json/` 文件类型桶，也不增加深层包装。

全项目保持 `00_研究背景` 至 `11_归档` 十二个顶层职责；`01_参考论文` 原文路径、B1–B5、T 线程、R1–R5 与现有引用不重编号。其他职责目录已具有明确边界，本轮不为外观移动内容。

## Impact · 同任务修复与验收

- `gen_acquisition_list.py`：目前共用 `TOOLS`；拆成 TF/BM 两个路径常量，BM 的动态导入和 JSON 读取一起更新，不能全局替换旧目录名。
- `自检脚本/verify_kb.sh`：BM 动态导入路径更新；TF 路径保留。
- 移动脚本的 `HERE/ROOT`：同级移动不改变根目录深度，逐个核对相对根路径；`recover_oa.py` 对 `build_biomech` 的同目录导入一起移动。`fetch_epmc_supp.py` 的默认报告路径必须改。
- 导航、生成器中的运行示例与产出页：按 BM 文件归属更新；历史执行日志不改写。TF README 删去现行 BM 主入口、指向新入口；BM README 写清构建、取件、入库、自检和取件总清单。
- 扫描命中字面旧目录的文件与行号已存机器清单；其中 TF 专用项保持原样。执行前还需核对动态拼接、CLI 默认值及已移动文件中裸文件名引用，静态扫描不是完整覆盖证明。
- 验收：Python 语法及本地构建/导入、BM 索引和总清单重生成、完整 21 项自检、原件/历史哈希、逐条目标唯一和原路径消失；不启动联网抓取、人体实验或重新裁定候选。

## Protected · 不迁移

原始 PDF/XML/视频、中文精读、已有备份（`.bak`、`.pre_*`）、历史检索日志、`11_归档`、`_research_run`、`.pi`、缓存、git 既有删除和无关变更均不清理或重排。`f15_snowball.json` 等未证明现行调用的留证文件不因文件名相近自动纳入。

## Rollback · 执行前留证

迁移前重新核验机器清单 SHA-256，保存所有将修改的调用方及导航的当时字节，不以 git HEAD 覆盖已有工作树。验证失败时恢复这些字节，依机器清单逐项逆向移动；移除新增 README 和确认空的目标目录。不得保留双份现行源码，历史备份不是第二份现行入口。
