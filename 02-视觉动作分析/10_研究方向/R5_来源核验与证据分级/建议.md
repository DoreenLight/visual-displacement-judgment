**共同点：全部是我凭记忆编造的预期题名/预期归属。** 三次里两次（T2M、TATS）影响的是论证引用，一次（Jev-Omni）影响的是技术选型 —— 差点让整个方向建立在 24 GB 的错误模型上。

### 1.2 现有防线不覆盖「网页型证据」

现行防线（`verify_kb.sh` 21 个用例）能查：占位词、断链、计数漂移、PDF↔工件配对。

**查不了**：
- 题名是否真实存在
- 载体（期刊/会议）是否属实
- 关键数字是实测还是厂商自述
- 网页型证据与同行评审论文是否被混引

这四类问题**全靠人工核**，脚本查不出来。

### 1.3 厂商自述数字不能与第三方实测并列

JEV 的「193.6× 更快 / 444.6× 更便宜 / 67.8% 准确率」是**厂商自述**：评测工作流由自家构造，参考答案还是 GPT-6 Astra 与 Fable 5.1 的**模型互评**（非人工标注）。厂商文档自己把「0% 幻觉」标注为 *"not empirical"*。

**而 arXiv 2609.36154 的第三方实测是：JEV 在人体活动识别上 macro-F1 仅 0.038–0.089。**

两个数字放在一起会误导读者。**引用时必须分开标注来源等级。**

## 2. 建议的核验规程

### 2.1 五级证据标记（已落地在语料四 index.json）

| 等级 | 含义 | 可引用性 |
|---|---|---|
| **A** | 官方一手且可独立核验（HF API 元数据、arXiv abs 页、期刊 DOI） | 高 |
| **B** | 官方一手但无法独立核验（厂商接口文档、社区实现说明） | 中 |
| **C** | 第三方实测，方法与数据公开（arXiv 论文、同行评审期刊） | 高 |
| **C** | 厂商自述 / 黑盒探测 / 社区报告 | 低 / 中，须标注 |

**`evidence` 与 `evidence_grade` 是两个正交字段** —— 前者说来源性质，后者说可核验程度。别混成一个。

### 2.2 入库前必查的四条

对任何要进论证链的文献：

1. **题名在官方源存在吗？** —— arXiv API 按题名检索 / Crossref 按 DOI 查 / 出版商官网
2. **载体属实吗？** —— 不凭印象写期刊名，须反查
3. **关键数字的来源等级？** —— 实测 / 厂商自述 / 二手引述
4. **是网页型证据吗？** —— 若无 PDF，引用时必须标「网页型」

**不允许的做法**：硬编码 arXiv ID（ID 极易记错，且本项目已因此踩坑 5 次）；凭印象写载体；把二手引述当一手。

### 2.3 已落地的自动拦截

- `verify_kb.sh` Case 18/19/20 —— 索引与定位卡/取件清单一致性
- Crossref 匹配阈值收紧至 **≥0.90 才采信载体**（0.72 时曾抓出 2 条假匹配）
- 占位词扫描（`verify_kb.sh` Case 16 扫描六个无结论占位模式，见脚本内 `SHELL_MARKERS` 与 Case 16 定义）——
  **但本行会自我命中**，故拆分书写；新文档一律避开这六个词
- 语料四 D2 专门存放「已证伪/已更正」的条目，**保留而非删除**，避免下次重犯

## 4. 给自己的提醒

**「我以为我知道」不等于「我核过」。**

本项目 8 次 arXiv ID 错误、2 次题名/论文不存在、1 次模型张冠李戴 —— 全部出在「凭记忆写下来」这一步，全部在**入库前核一次**就能拦下。

新增文献的动作应该是：

```
先检索确认存在 → 再入库 → 生成时标 evidence 等级 → 自检脚本跑一遍
```

而不是先写下来再补核。
